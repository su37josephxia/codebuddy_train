## 腾讯问卷连接器口径（务必记住）

- pluginId：`tencent-survey@workbuddy-connector-plugins-official`；当前状态 **`auth-required`**（bound:true / enabled:true，但授权未完成）→ **课堂前必须扫码 / 登录授权**，讲师准备清单已列为第一条。
- 能力：`create_survey`（纯文本 DSL 创建）、`get_survey`（回读结构）、`update_question`（改单题，需先取 question_id）、`list_answers`（回收，注意游标翻页）。场景 `scene=1` 调查。
- 投放链接：`https://wj.qq.com/s2/{survey_id}/{hash}`。
- DSL 语法：第一行标题；题目间空一行；**同一题标题与选项间不能空行**；选项不写 A./B. 前缀；题型 `[单选题] [多选题] [单行文本题] [多行文本题] [段落说明]`；`[必答]/[选答]`、`=== 分页 ===` 按现场版本语法。
- **`create_survey` 非幂等**：每调用一次真的新建一份问卷 → A 版标题标「测试·勿投放」、链接不外发、课后清理；改单题用 `update_question`。
- 边界：腾讯问卷视觉样式由平台模板决定，官方海报/角色图不等于能贴进问卷；素材只管**文字信息**（标题、欢迎语、选项、IP 名称）。这条写进了大纲与题目文档常见坑。

## 第 3 场四次调整：连接器与 MCP 的关系 + MCP 小实验（用户指令）

- 用户要求「讲清连接器和 MCP 的关系，并且可以做几个 mcp 的小实验」。大纲新增 **§4.5 连接器与 MCP 的关系**（6 分钟）与 **§5.4 MCP 小实验卡**（5 张）；同步 README、总纲第 3 场时间表内容要点，时间分配不变。
- **官方口径核实**：
  - WorkBuddy 连接器文档明确「从实现形态来看，连接器分为 **MCP + CLI（标准化协议）** 和 **Skill + CLI（内置脚本）** 两种形式」；「自定义连接器」按钮即**安装自定义 MCP 服务**；腾讯乐享授权页原文写「通过乐享知识库 MCP」。
  - MCP（Model Context Protocol，模型上下文协议）= 2024-11 由 Anthropic 发布的**行业开放标准**，类比「AI 应用的 USB-C」；解决 M×N 胶水代码 → M+N；服务端暴露 tools / resources / prompts；传输 stdio 或 HTTP/SSE；不替代 function calling，是把工具供给侧标准化。
  - 课堂口径：**MCP 是「接口的规矩」（协议层），连接器是「按规矩做好的插头」（产品层）**——连接器在协议之上多做授权、启停状态、失效重连、独立授权与最小权限、界面可见可管理。不是并列关系，也不是同义别名。
- **本机环境结论**：`~/.workbuddy/mcp.json` 只有 3 个内网服务（`sdd-gtm-board` / `POPO MCP` / `internal-gateway`），均不适合设计类学生课堂 → 小实验不装新 MCP，改用**现场已有官方连接器**做观察型实验。
