## 四、授课段详细设计（0-45'）

### 0-8'　① 专家及专家团概念定义

- **目标**：8 分钟建立"是什么"，不展开操作。先用官方定义把两个词钉死，再补一句能力边界。
- **内容要点**：
  - **专家**：一种**「角色切换」机制**——通过 **人设 + 方法论 + 工具链**，让 WorkBuddy 以特定领域专家的身份执行任务。它不是独立账号，也不会**主动获取系统权限**；只有配备 Skill / MCP 时，才在授权下间接访问文件或外部服务。
  - **专家团**：一支 **AI 协作团队**——由**主理人 + 成员专家 + 任务编排**组成，自动拆解任务、并行执行、完整交付。消耗较高，只在真正需要多角色协同时使用。
  - **两者关系**：专家解决"这一块谁来做、按什么标准做"，专家团解决"一整件事怎么拆、谁和谁配合"。
- **板书金句**（这一段收口）：**好的专家要有三样东西——身世（行业背景）、经验（方法论）、边界（什么能做、什么不能做）。**
- **讲法提示**：用本组角色分工做类比，一句带过；不打开平台演示，用法放到 27' 以后。权限那句要讲清——专家默认不碰系统权限，能力来自它挂载的 Skill / MCP 和授予的权限，避免学生误以为"专家比 Skill 权限更高"。

### 8-20'　② 和 Skill 的差异

- **目标**：把本节最容易混淆的三个概念分清楚。学生很容易把专家当成"另一个 Skill"，也容易以为专家团只是"多个专家堆在一起"。
- **内容要点**（投影核心对照表，三列分开讲）：

| 维度 | Skill | 专家（Agent 型） | 专家团（Team 型） |
| --- | --- | --- | --- |
| 定位 | 工具能力：让 AI 能做某件事 | AI 顾问：懂某个领域的 AI 角色 | AI 协作团队：自动拆解、并行执行、完整交付 |
| 类比 | 「工具」——赋予执行能力 | 「顾问」——切换专业视角 | 「团队」——多角色协同作战 |
| 典型内容 | 处理步骤、输出格式、脚本 | 行业背景、方法论、SOP、关联 Skill、安全边界 | 主理人 + 成员专家 + 任务编排 |

- **三者的边界**（同一张投影上补三行，为后面的公式埋线）：

| 组件 | 解决什么问题 | 一句话 |
| --- | --- | --- |
| 连接器 | 材料从哪来 | 把真实素材接进工作流 |
| Skill | 事情按什么流程做 | 把重复工序固化下来 |
| 专家 | 用什么专业眼光做 | 把专业视角固定下来 |

- **讲法提示**：不要下"专家是更高级的 Skill"这类结论，三者是不同维度。用一句话收口：**Skill 管流程，专家管眼光，连接器管材料。** 让学生记住各自解决什么问题，比记住定义更重要。三列表的落点在"典型内容"一行——专家写的是背景、方法论、边界，Skill 写的是步骤和脚本，一眼就能分辨。

### 20-27'　③ 使用场景

- **目标**：从"是什么"转向"什么时候用"，给判断标准，不做功能罗列。
- **内容要点**：

| 场景 | 该用什么 | 为什么 |
| --- | --- | --- |
| 写一份结构固定的方案、纪要 | Skill | 步骤稳定，要求不漏项 |
| 接入方案、官方素材、真实数据 | 连接器 | 有材料，输出才不发空 |
| 写一段有品牌调性的文案、定一版视觉风格 | 单专家 | 需要固定的专业视角和审美标准 |
| 一次出齐文案、海报、落地页，且彼此要对得上 | 专家团 | 多角色分工，统一约束下汇总 |
| 任务简单、只要一个结果 | 单专家即可 | 拆成团反而增加协调成本 |

- **什么时候组专家团**（板书判断标准，满足其一即可；否则用单专家更轻量）：
  1. 需要多个不相关的专业视角（如法律 + 财务 + 技术）；
  2. 需要交叉验证；
  3. 多个环节的产出要整合成一个交付物。
- **消耗提醒**：专家团消耗较高，只在真正需要多角色协同时使用；一件物料、一个视角，用单专家就够。
- **判断口诀**（板书）：**一件事一个视角找专家，一整套物料多个视角找专家团，流程重复找 Skill，需要真材料找连接器。**
- **讲法提示**：这一节是后面"万能公式"的预热，只讲选型逻辑，不讲操作。学生能说出"这件事该找谁"就够了。

### 27-38'　④ 使用方法（案例：校园毕业设计展）

- **目标**：用一个非游戏案例，让学生看见单专家与专家团的输出差异。案例统一为**校园毕业设计展物料**：一份宣传文案、一张海报长图、一个活动落地页。
- **内容要点**：
  1. **单专家跑一版**：调用一个文案专家，输入"为校园毕业设计展写一份宣传文案"，要求主题名、三条 Slogan、一段社媒短文。展示输出，学生看的是：有没有专业视角、语气是否统一、结构是否齐。
  2. **专家团跑一版**：同一个需求，先拆成三步板书出来：
     - 文案：主题名 / Slogan / 社媒短文 / 邀请函
     - 视觉：海报长图的配色、版式、主视觉元素
     - 结构：落地页的区块划分与报名区
     然后交给专家团分工完成，汇总成一套。学生看的是：三件物料之间的信息是否一致、主题和 Slogan 有没有互相打架。
  3. **并排对比**：耗时、完整度、专业度、物料间一致性，四项当场打分。
- **关键口径**：**案例只用毕业设计展，不碰游戏。** 学生在后面实践环节做的才是自己的游戏主题活动，这里不提前给答案。
- **讲法提示**：拆任务的板书一定要写在演示之前。让学生看到"专家团不是把一句话丢进去等结果，而是先把活拆清楚"。这也是后面实践中要他们照做的动作。

### 38-45'　⑤ 创建专家与专家团（现场建一个简单专家）

- **目标**：选 A，真创建。带学生从零建一个简单专家，建立"我也能配一个"的信心。专家团的创建讲配置思路，不在现场完整搭团。现场做"建专家 + 跑一句 + 改一项配置再跑一遍"的完整演示。
- **内容要点**：

**专家设计六要素**（投影，作为填写清单；第三列"写不好的后果"逐条念，这是本节最有价值的判断标准）：

| 要素 | 说明 | 写不好的后果 |
| --- | --- | --- |
| 行业背景 | 熟悉的行业、业务场景、典型约束 | 只说"熟悉互联网"→ 回答通用，不接地气 |
| 相关经验 | 岗位任务、方法论、分析框架 | 只说"经验丰富"→ AI 不知道怎么分析 |
| 角色定位 | 代表什么岗位能力、为谁服务 | 不明确 → AI 不知道以什么身份回答 |
| 关联 Skill | 可以调用哪些工具能力 | 没关联 → 只能聊天，不会干活 |
| 执行 SOP | 分析步骤：先做什么、再做什么 | 没流程 → 每次输出结构都不一样 |
| 安全边界 | 不能做什么 | 没写 → AI 可能越界决策 |

- **六要素对照示例**（口述，不另占投影表格）：建"毕设展文案专家"时，行业背景写"校园活动传播、面向在校生"，相关经验写"毕业展文案的方法论"，角色定位写"面向在校生的文案顾问，调性年轻、有设计感"，关联 Skill 挂上文案写作能力，执行 SOP 写"先定主题名，再写 Slogan，最后写社媒短文"，安全边界写"不虚构主办方信息、不编造往届数据"。平台上的名称、知识库等字段顺带一提即可。
- **现场动作**：照着六要素，带全班建一个"毕设展文案专家"，保存后跑一句"写一个叫'边界'的毕设展文案"，当场看输出。改一项（比如把角色定位里的"年轻、有设计感"改成"庄重、权威"），再跑一遍，让学生看到配置如何改变输出。
- **专家团配置思路**（讲清单，不现场搭）：**主理人 + 成员专家（文案 / 视觉 / 结构）+ 任务编排**。给每个成员写清职责与交付物、协作顺序，再加一条统一约束——"主题、亮点、时间地点、Slogan 四样，所有成员用同一份"。专家团消耗较高，只在需要多角色协同时使用。
- **讲法提示**：这是本场"我也能做"的落点。强调不用凭空想，把自己平时怎么带人、怎么定标准、哪些事不能做写出来，就是一个专家；把自己组的分工和协作顺序写清楚，就是一个团。回扣板书金句——**身世、经验、边界，三样齐全才算好专家**。

## 五、讨论及实践段详细设计（0-75'，独立计时）

### 0-8'　⑥ 实践任务发布

- **形式**：各组按第 2 节方案的物料清单，为自己认领的游戏主题活动做物料。同一份需求，先单专家做一版，再专家团做一版，对比后定稿。
- **输入材料**：第 2 节方案的物料清单 + 第 3 节报名问卷（落地页报名区要嵌入这份问卷）+ 前 3 节全部成果。
- **当堂产出**：物料包三件 + 双版对比记录，全部当堂完成。
- **物料包规格**（投影展示，全程可见）：

| 件 | 文件 | 规格 |
| --- | --- | --- |
| 1 | `宣传文案.md` | 活动主题名 / Slogan 3 条 / 社媒短文 / 报名邀请函 |
| 2 | `海报长图.html` | 750px 宽，含主题、亮点、时间地点、报名方式 |
| 3 | `活动落地页.html` | 至少 6 区块（首屏 / 介绍 / 亮点 / 日程 / 报名区 / FAQ），报名区嵌入第 3 节问卷 |
| 4 | `单专家与专家团对比记录.md` | 按下表填，写清最终选哪个及理由 |

- **对比记录表**（投影展示）：

| 对比项 | 单专家 | 专家团 |
| --- | --- | --- |
| 完成耗时 | | |
| 结构完整度 | | |
| 文案专业度 | | |
| 物料间一致性 | | |
| 最终选哪个，为什么 | | |

- **评判口径**（投影展示，全程可见）：

| 维度 | 权重 | 判断标准 |
| --- | --- | --- |
| 物料完整度 | 30% | 至少 3 件，与方案物料清单对得上 |
| 信息一致性 | 30% | 时间、亮点、Slogan 三件物料间不打架 |
| 链路可复现 | 20% | 落地页报名区嵌了第 3 节问卷 |
| 决策说理 | 20% | 对比记录能说清两版差异与选择理由 |

### 8-20'　实践 A：单专家版

- 各组用自己创建的专家，围绕同一份物料需求做一版**宣传文案**，留档。
- **讲师巡场，重点纠偏**：把专家当搜索框用；文案没带专业视角、写成通用套话；输出结构不齐。
- **提醒时间节点**：20' 进入专家团版。

### 20-55'　实践 B：专家团版（三件物料）

- 先把"文案 / 视觉 / 结构"三步写在纸上，再交给专家团分工，汇总成一套三件物料。
- 三件物料必须信息一致：主题、亮点、时间地点、Slogan 四样用同一份。落地页报名区嵌入第 3 节问卷。
- **讲师巡场，重点纠偏**：不拆任务直接把一句话丢给专家团；三件物料信息打架；落地页忘了嵌问卷。
- **提醒时间节点**：55' 进入讨论。

### 55-65'　对比讨论

- 各组对着两版输出，围绕三问讨论：
  1. 哪版信息更齐？差在哪里？
  2. 三件物料之间，时间、亮点、Slogan 对不对得上？
  3. 做一件物料选单专家还是专家团？做一整套呢？
- 各组在对比记录表上填完"最终选哪个，为什么"。

### 65-75'　万能公式总结与产出④收口

- **万能公式**（板书，全场最后一条）：

```
连接器（拿素材） + Skill（定流程） + 专家（保专业） = 高质量定制化成果
```

- **收口动作**：各组在对比记录末尾写下一句"我们组后续采用的搭配策略"，物料包定稿，按 `组号-游戏名-物料包` 命名，当堂收齐。
- **用途交代**：这套物料是第 5 场现场互动工具的素材来源，也是第 7 场竞演 PPT 的组成部分。无课后作业。

## 六、产出与衔接

- **本场产出** → 物料包（宣传文案 + 海报长图 + 活动落地页）+ 单专家 vs 专家团对比记录。
- **下一场衔接**：第 5 场进入实践节，学生用本场收口的万能公式独立完成现场互动工具。第 4 场的物料、第 3 节的问卷、第 2 节的方案，一起成为后续竞演 PPT 的材料。

## 八、设计逻辑说明

- **认知递进**：概念定义 → 区分三者边界 → 使用场景 → 看别人怎么用 → 自己建一个 → 自己动手做。六步从认识到动手，逐层推进。
- **案例分离**：讲授段用毕业设计展，实践段用游戏主题活动。讲授只给方法，练习才给真题，避免提前讲掉答案。
- **评图式讨论**：沿用设计专业熟悉的"对比、点评、归纳"方式，让学生从两版输出的差异中自己得出结论。
- **收口定位**：本场是四节授课节的最后一节，万能公式在这里收口，后三节学生凭公式独立实践。

## 九、来源说明与课前核对

- **专家与专家团**：使用 WorkBuddy 平台内置的专家中心能力，不预制、不自建平台外的东西。定义与能力边界按官方口径：专家是「角色切换」机制（人设 + 方法论 + 工具链），本身不主动获取系统权限，仅在配备 Skill / MCP 时于授权下间接访问文件或外部服务；专家团由主理人 + 成员专家 + 任务编排构成，消耗较高，只在真正需要多角色协同时使用。
- **课前必做**：
  1. 实测专家中心，确认至少有一个现成专家和一个专家团可直接调用，作为演示兜底；
  2. 走一遍创建专家的完整流程，确认行业背景、相关经验、角色定位、关联 Skill、执行 SOP、安全边界六项在平台上都有对应位置，名称与知识库等字段一并说明；
  3. 准备毕业设计展的需求描述，现场跑通单专家版与专家团版各一次。
- **风险提示**：平台专家中心的入口、分类、创建字段可能变动，开课前实测一遍。若演示专家临时不可用，切到内置能力兜底，课堂重点是"选型逻辑 + 差异判断"，不是记住某个专家的名字。
