## 二、教学目标（可检验）

1. 能说清连接器解决什么问题：无依据、无素材、凭空生成；能复述官方定义里的三个要素（外部服务 / 授权 / AI 工作流）。
2. 能区分「一次性粘贴文字」与「建通道、文件持续在场」：改动源方案后更新问卷，信息跟着变。
3. 能按官方文档说出四类能力（数据查询 / 服务调用 / 文件管理 / 消息通知）与两种实现形态；能独立完成添加授权、三种使用方式、授权失效重连、停止使用、解绑，以及用自然语言安装 / 查看 / 卸载。
4. 能用腾讯问卷连接器创建问卷、写出合规的纯文本问卷描述、取回投放链接，并回读结构、修正单题。
5. 能说清「接上之后会读写什么」（信息收集四类）与权限边界三条，理解「用户写入数据需明确指令确认」「对外发送前二次确认」「连接器自身读写不消耗积分」。
6. 当堂交出产出③，对比记录能指出哪些信息只有接入材料后才准确。
7. 能用自己的话说清 **MCP 是「接口的规矩」，连接器是「按规矩做好的那个插头」**：MCP 是实现协议，连接器是带授权与边界的产品封装，二者不是并列关系，也不是同一个东西的两种叫法。
8. 通过小实验能指出「工具是挂上去的」：启用前只能给一段文本，启用后才能真正在外部服务里把东西建出来；断开即失去该能力。

## 四、`10-40'` 连接器原理（30 分钟，本场主体）

> **段内微调**：新增 4.5「连接器与 MCP 的关系」占 6 分钟，从 4.1 与 4.4 各压缩 3 分钟；重新分配后为 4.1（5'）→ 4.2（8'）→ 4.3（7'）→ 4.4（4'）→ 4.5（6'），合计仍 30 分钟。`10-40'` 总时长与总纲一致，不重排。
>
> **重编说明（五次调整）**：4.2 与 4.4 按官方 Connector 文档的小节顺序重排，投屏时照这个顺序走——`连接器` → `连接器能做什么` → `连接器的配置与使用` → `使用示例` → `自定义连接器` → `注意事项与重点提示`。4.2 讲前两个与口径修正，4.4 讲后四个；4.3 的教学对比与 4.5 的关系段不动，时长不变。

### 4.1 从问题切入（10-15'）

现场断开所有材料，用腾讯问卷连接器创建一版「XX 活动报名问卷」，投屏 A 版：标题只有活动名、时间地点写「待定」、亮点多选题是「游戏、奖品、表演」、欢迎语一句套话。板书三问：它凭什么知道时间地点？凭什么知道亮点？凭什么知道该问什么？结论落在：**没有真实材料，输出只能靠编**。

> 这一版要在问卷标题里标「测试·勿投放」，且不外发链接（见 §六）。

### 4.2 连接器是什么：按官方文档讲（15-23'，8 分钟）

**① 官方定义（原文，逐字上屏）**

> 连接器用于将 WorkBuddy 与外部服务对接，将外部数据和能力引入 AI 工作流。通过配置连接器，您可以让 WorkBuddy 在获得授权后访问和操作第三方服务，实现数据互通与能力扩展。

拆成三句人话：**一端是 WorkBuddy 的 AI 工作流，一端是外部服务，中间那道门是授权**。没有授权，就没有通道。再点一次官方用词「访问和操作」——它既能读，也能按指令去外部服务里做事。

**② 官方补充三句（原文要点，不展开）**

1. 从实现形态看，连接器分为 **MCP + CLI（标准化协议）** 与 **Skill + CLI（内置脚本）** 两种形式，二者在**数据收集和权限边界上遵循一致原则**。（MCP 是什么、和连接器什么关系，见 4.5；本段不讲协议细节与开发。）
2. 当前已支持 **QQ 邮箱、腾讯文档、腾讯乐享、腾讯会议、TAPD、腾讯网盘**等连接器，同时支持**自定义连接器**；**新增连接器后，相关隐私协议条款将同步更新**。
3. 课堂用的**腾讯问卷连接器**是会话内官方连接器插件，**不在上面这张内置清单里**；授权方式以现场页面提示为准。两张清单分开讲，不混为一谈。

**③ 连接器能做什么（官方表格，四列照抄 + 本场对应动作）**

| 场景 | 官方说明 | 官方示例 | 本场对应动作 |
|---|---|---|---|
| 数据查询 | 从外部数据源获取信息 | 查询数据库、检索文档 | 检索官方素材文档、读取方案 |
| 服务调用 | 调用第三方 API 完成操作 | 发送邮件、创建日程 | **通过腾讯问卷连接器创建在线问卷、回读结构、改单题（本场重点）** |
| 文件管理 | 访问云端存储与文件系统 | 读取网盘文件、上传附件 | 读取方案文件、官方图片 |
| 消息通知 | 与即时通讯工具集成 | 发送企业微信 / 飞书消息 | 把投放链接交到后续物料 |

官方原文一句：「通过连接器，WorkBuddy 可以在任务中调用外部服务的能力，完成数据查询、服务调用、文件管理和消息通知等操作。」

**④ 口径修正（本次重编的重点）**

原稿把连接器讲成「读进来 + 写出去的**双向通道**」，这不是官方文档的表述，容易让学生以为接上就会自动往外部服务写东西。按官方口径改成一句：**接入是引入，写入要下指令**。依据有两处：

- 四类能力里的「**服务调用**」＝调用第三方 API 完成操作，本身包含写；
- 「注意事项 → 信息收集与使用」把**用户写入数据**单列一类：**非必要，代发邮件、创建 / 编辑文档、创建会议等，需您明确指令确认**。

创建问卷就是一次「用户写入数据」，必须由学员明确说出「创建问卷」。这条同时是课堂纪律的依据：A 版标「测试·勿投放」、链接不外发、发布前二次确认、课后清理测试问卷。

**⑤ 本场看点**：学生第一次看到「AI 不只生成文件，还能在真实平台上把东西建出来」，前提是**已授权 + 明确指令**。

### 4.3 关键区分：一次性粘贴 vs 持续在场（23-30'）

| 对比项 | 复制文字进对话框 / 单次上传 | 连接器建通道 |
|---|---|---|
| 材料在哪 | 只在这一条消息里 | 整个任务期间持续在场 |
| 源文件改了 | 要重新复制一遍 | 重新生成时读到最新内容 |
| 多份材料 | 逐条贴，容易漏 | 授权范围内按需读取 |
| 跨任务复用 | 每次重来 | 通道保留，切换任务仍在 |
| 能做的动作 | 只能读这段内容 | 可读云端文件、可查数据、可创建问卷、可发通知 |

**现场演示**：接入方案文件 → 创建 B 版问卷 → 改方案里的时间 → 用 `update_question` 更新问卷里那道时间题 → 在线问卷跟着变。这是本场最直观的一击，也是题目文档点名的常见坑（学生直接把方案文字复制进对话框，以为这就是连接器）。

> 注意：`create_survey` 是**非幂等**写操作，每调用一次就真的新建一份问卷。演示「改方案后更新」优先用 `update_question` 改单题，不要反复重建整份问卷。

### 4.4 配置、使用与边界：官方文档后半段（30-34'，4 分钟）

> 讲法定位：官方文档「连接器的配置与使用」「使用示例」「自定义连接器」「注意事项与重点提示」四节的压缩版。只到「会用、懂边界」，不到「会开发」。B 的具体操作放到 §五 演示段带练，这里只讲清有哪些状态、边界在哪、接上之后会读写什么。

**A. 添加连接器（官方 4 步）**
侧边栏「专家·技能·连接器」→ 选中「连接器」页签进入管理页 → 找到需要的连接器，点卡片右上 `+` → 按页面提示完成登录、授权或其他配置 → 完成后即可使用。腾讯问卷连接器需扫码 / 登录授权，**课前必须完成**。

**B. 使用连接器（官方三种方式，原文口径）**

1. **从连接器页面发起对话**：管理页找到已授权的连接器，点卡片右上「去对话」，即可直接开始使用。
2. **创建任务时启用**：新建任务时点输入框左下 `+` > 连接器，在弹窗中开启需要使用的连接器；尚未完成授权的，先完成授权才能使用。
3. **执行任务时按需连接**：任务执行中需要使用尚未连接的连接器时，输入框上方会自动显示连接引导卡片；点击卡片完成授权后，**WorkBuddy 自动继续执行当前任务，无需重新发起对话**。

**C. 授权页上会看到什么（官方使用示例，投屏截图）**

| 官方示例 | 学员会看到的 | 教学落点 |
|---|---|---|
| QQ 邮箱 | 扫码授权 → 手机端确认权限清单：账号信息 / 读取收件箱内近一个月邮件 / 代为发送邮件 / 删除邮件（可选）→ 同意授权 → 卡片名称旁出现**绿色圆点**、右侧出现「去对话」 | 授权不是点一下「同意」，是看清一份权限清单 |
| 腾讯乐享 | 授权确认页写明「通过乐享知识库 MCP」将能：按你拥有的权限访问知识库 / 搜索查询内容 / 协助创建与管理内容 → 微信或手机号登录 → 确认账号信息与权限 → 继续 | 「不超出已有权限范围」在授权页上是看得见的 |

官方提示：QQ 邮箱授权成功时要点浏览器弹窗中的「打开」完成连接，**取消或直接关闭网页可能导致操作中断，需要重新配置连接器**；不同连接器的连接与授权方式可能不同，其他以实际页面提示为准。

**D. 授权失效后重新连接（官方 4 步 + 提示）**
出现「连接器需要重新连接」卡片（提示「此连接器的授权已失效，请重新连接以继续当前任务」）→ 点「重新连接」，按该连接器已有的授权方式完成登录、扫码或授权 → 授权成功后卡片显示已连接，**WorkBuddy 自动重试刚才失败的那一步，无需重新发起对话** → 不想重连可点卡片右上关闭按钮，此时不重试，任务需完成重连后才能继续使用该连接器；失败时提示「连接失败，请重试。」，可再次点击重新连接。

> **官方提示（易考易错）**：只有连接器明确返回**授权失效**时才会出现这张卡片；**网络超时、服务异常或没有权限不会提示重新连接**；同一步骤重新连接后**只会自动重试一次**；也可在对话里主动说「重新连接企业微信」。

**E. 停止使用 / 解绑 / 对话管理（官方三节，原稿只讲了一半）**

- **停止使用**：只想让某个连接器不再参与任务 → 输入框左下 `+` > 连接器 → 弹窗中关闭对应连接器的启用状态。
- **解绑**：管理页选中已连接且需解绑的连接器 → 弹窗点「解绑」→ 系统提示已解绑并恢复为未连接状态。
- **通过对话管理**（官方，自然语言）：说「帮我安装 QQ 邮箱连接器」即可引导安装；问「我安装了哪些连接器」会列出已安装及状态，**「已授权但当前关闭」的也会列出，它们平时不参与任务、容易被遗忘**；明确要求卸载时弹出确认窗口，列出即将移除的连接器与数量，确认后完成卸载，**内置连接器不支持卸载**。

**F. 自定义连接器（官方）**
管理页右上角「自定义连接器」按钮 → 安装自定义 MCP 服务，配置方式与 MCP 配置类似。本场只点入口，不做配置、不写代码、不装服务（见 4.5 与实验 E）。

**G. 接上之后会读写什么（官方「信息收集与使用」表，逐行上屏）**

| 收集项 | 类型 | 官方用途 |
|---|---|---|
| 第三方账号标识 | 必要 | 邮箱地址、账号 ID 等，用于在第三方服务中识别身份 |
| 授权凭据 | 必要 | OAuth Access / Refresh Token，或手动填写的 API 密钥 |
| 第三方业务数据 | 必要 | **仅在您的指令触发时按需读取**（邮件、文档、知识库、会议、TAPD 项目数据等） |
| 用户写入数据 | 非必要 | 代发邮件、创建 / 编辑文档、创建会议等，**需您明确指令确认** |

这张表是「基础讲解」里最该讲清的一页：学生关心的不是接口，是**接了之后我的数据会怎样**。G 与 4.2④ 的口径修正正好互相印证。

**H. 权限边界三条（官方原文）**：每个连接器独立授权 / 不主动定时抓取 / 不超出您已有权限范围。

**I. 注意事项四条（官方，压缩成四句）**

- **安全提示**：授权信息要确保正确；授权后可随时通过开关禁用或断开；建议定期检查连接器状态。
- **积分提醒**：**连接器自身的读写不消耗积分**；WorkBuddy 对**外部数据**进行理解、汇总时会消耗积分。
- **第三方共享与免责**：本质是「与第三方服务交互」，凭据由 WorkBuddy 维护以便代为调用；自定义连接器的访问范围由配置决定，WorkBuddy 不预设范围，启用前审慎评估。
- **使用建议**：调用产生的访问、读写、消息发送**均以你本人身份与授权范围执行**，涉及对外发送、内容修改前再次确认目标对象与内容；第三方服务异常优先查看该服务状态与协议；API 密钥与 Token 妥善保管，不再使用的连接器及时撤销授权。

**课堂纪律由 G / H / I 直接推出**：创建问卷属于「用户写入数据」，需明确指令；发布投放链接、修改已发布内容前再确认一次；A 版链接不外发、课后清理测试问卷。

### 4.5 连接器与 MCP 的关系（34-40'，6 分钟，本次新增）

> 段内压缩而来：4.1 与 4.4 各让出 3 分钟，`10-40'` 总时长不变。本段是 4.2「两种实现形态」那句话的展开，也是 §五 小实验的知识底子。

**一句话关系**：**MCP 是「接口的规矩」，连接器是「按规矩做好的那个插头」**。二者不是并列的两种工具，也不是同一个东西的两种叫法——MCP 在下面，连接器在上面。

**类比（板书只画这一张）**：MCP ≈ USB-C 接口规范，连接器 ≈ 一个具体的 U 盘 / 充电器。规范只规定「怎么接」，插头才决定「接的是哪个服务、能干什么」。

**分层**（从上往下念一遍，不要求记）：

| 层 | 是什么 | 课堂上看得见的例子 |
|---|---|---|
| 你 / 任务 | 说需求的人 | 「做一份活动报名问卷」 |
| 连接器（产品层） | 带授权、状态、边界的成品单元 | 腾讯问卷连接器卡片：绿点、去对话、可关闭、可解绑 |
| MCP（协议层） | 规定「怎么描述工具、怎么调用、怎么回传」的开放标准 | 工具暴露、上下文共享、可组合的工作流、本地运行的安全边界 |
| 外部服务 | 真正存数据的地方 | 腾讯问卷平台上的那份在线问卷 |

**为什么需要这一层协议**（讲一句就够）：没有统一规矩时，每个 AI 应用接每个外部服务都要单独写一套适配，是「应用数 × 服务数」的重复活；有了统一协议，服务方实现一次，支持协议的应用都能接。

**连接器在 MCP 之上多做了什么**（这才是学生天天看见的部分）：授权与登录、启用 / 关闭开关、连接状态与失效重连卡片、独立授权与最小权限、界面上可见可管理、失败时的提示与重试。协议只管「怎么接」，**「能不能接、谁来授权、边界在哪」是产品层的事**。官方连接器文档里，腾讯乐享的授权页写的就是「通过乐享知识库 MCP」；连接器管理页的「自定义连接器」按钮，本质也是安装自定义 MCP 服务。

**三条边界**（防止讲歪）：

1. **不是所有连接器都走 MCP**：官方明确两种实现形态——MCP + CLI（标准化协议）与 Skill + CLI（内置脚本），二者在数据收集与权限边界上遵循一致原则。
2. **MCP 不是某一家产品专属**：它是 2024 年出现的行业开放标准，常被比作「AI 应用的 USB-C」；课堂上不展开厂商、版本与年份考据。
3. **学生不用会配**：本场只让学员知道「还有自定义连接器这个入口」，**不做配置、不写代码、不装服务**。

> 讲法定位：这一段是把 4.2 那句「MCP + CLI」讲成人话，不是新增一门技术课。收口一句「协议管怎么接，连接器管接什么和能不能接」，随后进 §五，用小实验让学生亲眼看见「能力是挂上去的」。

## 五、`40-70'` 素材接入演示（30 分钟）

### 5.1 接入什么

| 材料 | 来源 | 接入方式 | 用在问卷哪里 |
|---|---|---|---|
| 第 2 节活动策划方案 | 本组产出② | 本地文件 / 腾讯文档 | 问卷标题、欢迎语里的时间地点、报名区字段 |
| 三个活动亮点 | 方案第 5 项物料清单 | 同上 | 「现场最想玩什么」多选题的选项 |
| 目标人群描述 | 方案第 3 项 | 同上 | 参加人数、到场时段两题的选项 |
| 官方名称与素材调性 | 游戏官网 / 官方素材包 | 图片文件 / 文档检索 | 问卷标题、欢迎语措辞、IP 名称不写错 |

> **边界提醒**：腾讯问卷的视觉样式由平台模板决定，官方海报 / 角色图不等于能直接贴进问卷。素材的作用是让**文字信息**准确、调性一致，不强求配色还原。这条正好用来讲「连接器能接材料，但目标平台能呈现什么由平台决定」。

### 5.2 演示顺序

1. **授权**〔实验 A · 工具清单前后对比〕：先不启用，问一句「你现在能创建一份线上问卷吗」并投屏回答（只能给一段问卷文本）；再完成腾讯问卷连接器登录，确认卡片显示已连接状态，用**同一句话**再问一次（可以真的建出来）。课前先做一遍，现场只复核。
2. **启用**：创建任务时用方式②（输入框左下 `+` > 连接器）挂上腾讯问卷连接器；方案文件与官方素材同时作为上下文接入。
3. **写问卷描述**：用纯文本 DSL 写出问卷标题 + 引导语 + 8–10 道题（语法见 5.2.1）。
4. **创建并取回链接**：连接器调用 `create_survey` → 返回 `survey_id` 与 `hash` → 拼出投放链接 `https://wj.qq.com/s2/{survey_id}/{hash}`，当场打开验证。
5. **回读与改单题**：`get_survey` 确认题目结构 → `update_question` 改一道题 → 再回读一次，说明「改的是线上那份，不是本地文件」。
6. **方式③ / 实验 B · 断开再问**：任务内关闭该连接器的启用状态，再问「把刚才那份问卷加上一道题」，投屏看它从「能改线上那份」变成「只能给你一段文本」；随后重新启用，演示引导卡片与自动继续。两个实验共用同一次演示，不额外占时。

### 5.3 常见坑（讲师巡场重点）

| 坑 | 表现 | 处置 |
|---|---|---|
| 把复制粘贴当连接器 | 方案文字贴进输入框，输出仍会跑偏 | 回看 4.3 的「改方案 → 更新问卷」演示 |
| 授权没走完 | 卡在扫码 / 登录页，`create_survey` 报未授权 | 课前统一授权，现场确认已连接状态 |
| 以为连接器只能读 | 只敢让它读文件，最后手工去问卷后台建表 | 明确点出「服务调用」这一类能力 |
| 官方图片当成能贴进问卷 | 花时间调配色、找头图 | 说明平台样式边界，素材只管文字信息 |
| DSL 格式写错 | 题目内空行、选项带字母前缀 → 创建失败 | 按 5.2.1 骨架写，课前验证语法 |
| 反复重建问卷 | 每改一次就 `create_survey`，留下一堆重复问卷 | 改单题用 `update_question`；A 版标「测试·勿投放」 |
| 授权失效 | 执行中断在半路 | 认「重新连接」卡片，不重开任务 |
| 和 Skill 混用 | 以为接了材料就能自动按规格出题 | 材料归连接器，题目结构归流程，本场只练材料 |

## 六、`70-105'` 上手实操（35 分钟）

**任务**：同一个需求「做一份本组活动的报名问卷」，两版都通过腾讯问卷连接器创建真实在线问卷，对比后定稿正式版投放链接。

| 步骤 | 动作 | 时间 |
|---|---|---|
| A 版 | 断开所有材料，用连接器创建一版（标题标「测试·勿投放」） | 8' |
| 接入 | 挂载方案文件 + 官方素材包，确认腾讯问卷连接器已连接 | 7' |
| B 版 | 接入材料后创建正式版，取回投放链接并当场打开 | 10' |
| 对比 | 四行对比 + `get_survey` 回读两版结构 | 6' |

## 七、产出③规格与合格线

**腾讯问卷在线报名问卷**，8–10 题，四类题型齐全：

| 题型 | 示例 | 问卷题型 | 信息必须来自 |
|---|---|---|---|
| 基本信息 | 姓名、手机、所在城市 | 单行文本题 | — |
| 报名意向 | 参加人数、偏好时间段 | 单选题 | 方案的活动流程 / 目标人群 |
| 需求调研 | 想看什么环节、想要什么周边 | 多选题 | 方案的三个活动亮点 |
| 开放题 | 对活动的期待 / 建议 1–2 题 | 多行文本题 | — |

**交付三件**：

1. 正式版投放链接 `https://wj.qq.com/s2/{survey_id}/{hash}`（当场可打开、可填写）
2. **素材接入记录**：一张表写清「材料 / 来自哪里 / 通过什么接入 / 用在了问卷哪里」+ A / B 两版链接 + 四行对比 + 一句话结论
3. **问卷纯文本描述**（DSL 存档，便于复现与改单题）

**合格线**：

- [ ] 问卷信息与第 2 节方案一致（标题、时间、地点、亮点对得上）
- [ ] 8–10 题，题型多样，不重复不诱导，且**通过腾讯问卷连接器创建**（有投放链接与 `survey_id`）
- [ ] 使用记录写清「材料通过连接器进入工作流、持续在场；成果通过腾讯问卷连接器写入外部服务」
- [ ] 能对比出「接材料」与「凭空生成」两版的质量差异，并给出正式版投放链接

> **口径校准**：样例 `03-素材接入记录.md` 自检清单原写「题目 6 道」、且以 `03-报名问卷.html` 为交付物。现统一为 **8–10 题 + 腾讯问卷在线问卷**；样例 HTML 保留作**内容示意**，不是课堂交付形态。样例已同步标注。

**讲师点评要点**：现场做一次「断开材料创建 / 接入材料创建」的对比，差异最直观；点评只抓「信息对不对得上方案、链接能不能真的发出去」，不评平台皮肤。

## 八、与相邻概念的边界（贯穿全场，不单独成段）

| 概念 | 管什么 | 本场怎么讲 |
|---|---|---|
| 上传文件 / `@` 引用 | 一次性上下文 | 4.3 对比表，作为对照物 |
| 连接器（数据引入） | 外部数据和能力进入工作流 | 官方定义；读方案、读官方素材 |
| 连接器（服务调用 / 用户写入数据） | 成果写到哪去 | 腾讯问卷连接器建出在线问卷；需明确指令确认 |
| Skill | 事情按什么流程做 | 只点名，不展开（第 2 场已讲） |
| 专家 | 用什么专业眼光做 | 只点名，不展开（第 4 场讲） |
| 资料库 | 资料集中管理与检索 | 只提一句，与外部服务通道区分 |
| MCP | 连接器底层的接口协议 | 4.5 讲清关系；只到「接口的规矩」，不讲配置与开发 |

板书收口：**连接器把外部数据与能力接进工作流；要往外部服务写东西，得有授权和明确指令**。MCP 是它脚下那套接口规矩。万能公式的完整整合留到第 4 场，本场不提前收。

## 十、讲法边界与常见坑

- 只讲「会用、懂边界」。**MCP 讲到「是什么、和连接器什么关系」为止**（4.5），不讲协议报文、API Key、Token、Server 配置与自定义连接器开发；小实验只做观察，不要求学生配置。
- **基础讲解以官方 Connector 文档的小节名称与原文措辞为准**（4.2 / 4.4），不自造「双向通道」「桥梁」这类口径；写入侧按官方「服务调用」+「用户写入数据需明确指令确认」来讲。
- **两张清单分开讲**：官方内置连接器（QQ 邮箱、腾讯文档、腾讯乐享、腾讯会议、TAPD、腾讯网盘等）与课堂用的腾讯问卷连接器插件不混为一张；授权方式以现场页面提示为准。
- 不把「授权」讲成一个按钮：官方使用示例里要看清权限清单，授权成功后还要点浏览器弹窗的「打开」，否则可能中断。
- MCP 关系段用类比收口（接口规范 / 插头），不讲成技术标准编年史、不做厂商与年份考据；学生只需记住「协议管怎么接，连接器管接什么和能不能接」。
- 腾讯问卷只讲三个动作：创建、回读、改单题；不讲后台全部功能与回收数据分析（后者属第 6 场）。
- 不把连接器讲成「上传文件按钮」，也不讲成「更高级的 Skill」。
- 不做跨场回溯、不提前收口万能公式；本场只埋「连接器管材料，也管把成果写出去」这一句。
- 常见坑：原理段讲成产品功能罗列；演示段只点不练；实操段学生跳过 A 版直接做 B 版（对比就没了）；把测试版链接发出去；反复 `create_survey` 留下一堆重复问卷。
- 官方界面、按钮名与 DSL 题型标记以现场版本为准，课前按实际界面截图核对。
