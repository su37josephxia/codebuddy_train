## 二、教学目标（可检验）

1. 能说清连接器解决什么问题：无依据、无素材、凭空生成；能复述官方定义里的三个要素（外部服务 / 授权 / AI 工作流）。
2. 能区分「一次性粘贴文字」与「建通道、文件持续在场」：改动源方案后更新问卷，信息跟着变。
3. 能按官方文档说出四类能力（数据查询 / 服务调用 / 文件管理 / 消息通知）与两种实现形态；能独立完成添加授权、三种使用方式、授权失效重连、停止使用、解绑，以及用自然语言安装 / 查看 / 卸载。
4. 能用腾讯问卷连接器创建问卷、写出合规的纯文本问卷描述、取回投放链接，并回读结构、修正单题。
5. 能说清「接上之后会读写什么」（信息收集四类）与权限边界三条，理解「用户写入数据需明确指令确认」「对外发送前二次确认」「连接器自身读写不消耗积分」。
6. 当堂交出产出③，对比记录能指出哪些信息只有接入材料后才准确。
7. 能说清 MCP 是什么：模型上下文协议、**开放通用协议标准，不属于任何产品，Claude / Cursor / 各类 Agent 通用**、USB-C 规范类比、协议三部分组成（规范 / Server / Client）、四项核心价值，以及一次调用里的三种角色（Host / Client / Server）。
8. 能用自己的话说清 **「MCP ≠ 连接器」**：MCP 是通用通信标准，连接器是 WorkBuddy 平台里的接入组件；很多连接器底层用 MCP 实现，但还有 Skill + CLI 型不走 MCP。能填出五行区别表（本质 / 归属 / 范围 / 包含内容 / 关系），并说出完整链路与三个常见误区。
9. 通过公共 MCP 接入实验能指出「工具是挂上去的」：接上前工具清单里没有 fetch、回答只能凭已知信息；接上后状态灯变绿、多出 fetch、回答里出现网页真实内容；能填出三列记录卡。
10. 通过嵌入演示的对照 A / B 能指出「启用前只能给文本、启用后能真的建出来；断开即失去该能力」。

### 4.2 MCP 是什么：先把协议讲清楚（8'）

> 依据：[WorkBuddy MCP 文档](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/MCP-Guide)、[MCP 配置文档](https://www.workbuddy.cn/docs/ide/User-guide/MCP)、[官方 Connector 文档](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Connector) 的「自定义连接器」小节。讲法参考：[MCP 与 WorkBuddy 连接器的区别](https://www.doubao.com/thread/xrWP0PZw2j4F6Qowr)。**本节只讲协议，不提连接器**。

**① 官方定义（逐字上屏）**

> MCP（Model Context Protocol，模型上下文协议）用于将外部工具和服务接入 WorkBuddy，让 AI 获得发送通知、连接业务系统、访问数据源等扩展能力。
>
> MCP 旨在解决大模型（LLM）与外部数据源及工具之间无缝集成的需求。它通过标准化 AI 系统与数据源的交互方式，帮助模型获取更丰富的上下文信息，从而生成更准确、更相关的响应。

拆成一句人话：**它是一套「AI 和外部系统怎么互相发消息」的统一对话语言**。怎么发现工具、怎么调用、怎么传数据，都由协议规定。

**② 定位与归属（本次重编补齐，学生最容易搞混的一层）**

- MCP 是**开放通用协议标准**，不属于任何一家产品，也不是 WorkBuddy 独有的。
- Claude、Cursor 以及各类 Agent 都在用同一套协议；一个写好的 MCP 服务，所有支持 MCP 的 AI 都能直接用。
- 它**脱离 WorkBuddy 照样能跑**。这一条是 4.4「MCP ≠ 连接器」的根据，先在这里立住。

**③ 官方类比（成对类比的前半，板书只画规范这一侧）**

MCP 可以理解为 AI 的「USB 接口」；更贴切地讲，它像 **USB-C 规范**：定义电压与通信格式，任何设备按这个规范做就能互通。规范本身不是设备，也不属于某一家厂商。成对类比的后半「一根带芯片的 USB-C 数据线」留到 4.5 讲连接器时再出现，两半合看才讲得清区别。

**④ 协议由三部分组成（参考内容补）**

| 组成 | 是什么 | 本场例子 |
|---|---|---|
| 协议规范 | 统一的通信规则与工具 / 资源模型 | 怎么描述工具、怎么调用、怎么回传 |
| MCP Server | 服务端，暴露工具与数据 | 公共 MCP：Fetch |
| MCP Client | 客户端，对接 AI 宿主 | WorkBuddy 里发起工具调用的环节 |

**⑤ 核心价值四项（官方表格，逐行上屏）**

| 能力 | 官方说明 | 课堂上的说法 |
|---|---|---|
| 上下文共享 | 向模型提供文件内容、数据库记录、业务信息等上下文 | 把真实材料送进模型 |
| 工具调用 | 将文件读写、接口调用、消息发送等能力暴露给模型 | 模型手里多出一批工具 |
| 可组合工作流 | 多个工具和服务通过 MCP 串联，组成自动化流程 | 几步动作可以连起来做 |
| 数据控制 | 支持本地或受控方式运行，兼顾灵活性与安全性 | 数据在哪里跑可以管住 |

> 口径说明：MCP 配置文档的四项写作「上下文共享 / 工具暴露 / 可组合的工作流 / 安全性（通过本地服务器运行，避免将敏感数据上传至第三方平台）」，与上表一致。课堂统一用 WorkBuddy MCP 文档这版措辞，不混用两套词。

**⑥ 三种角色与一次调用（讲清楚 MCP，这一步不能省）**

| 角色 | 是什么 | 本场例子 |
|---|---|---|
| Host 宿主 | 正在用的 AI 应用 | WorkBuddy |
| Client 客户端 | 应用内部负责与服务器通信的组件 | 任务里的工具调用环节 |
| Server 服务器 | 暴露工具与数据的小服务 | 公共 MCP：Fetch |

一次调用链路：你说一句需求 → WorkBuddy 判断要用哪个工具 → 通过 MCP 找到 Server 上的工具 → Server 执行（读网页 / 查时间）→ 结果回传，成为模型的上下文 → 模型据此回答。板书一句：**工具是挂上去的，接上前模型手里没有这件工具**。

**⑦ 公共 MCP 从哪里来**

- 官方文档：WorkBuddy 提供现成的 MCP 资源入口，可访问腾讯云 MCP 市场获取更多开放生态能力；MCP 标签页支持一键安装，安装成功显示绿色状态，安装失败显示红色状态。
- 官方协议站：一组官方参考实现（Everything / Fetch / Filesystem / Git / Memory / Sequential Thinking / Time），以及 MCP Registry 里由厂商与社区发布的公共 Server。
- 本场选 **Fetch**：官方参考实现、只读公开网页、不需要账号与密钥、不会对外发消息。备选 **Time**：纯本地计算，网络不通时用它。
- 讲到这里为止：不讲协议报文、SDK、版本号与厂商考据。

### 4.3 公共 MCP 接入实验 F（9'，本场主实验）

### 4.4 MCP ≠ 连接器：先把区别讲清楚（4'，引入页）

> 位置说明：这段在实验之后讲。学生刚看过一段配置、盯过状态灯，此时点破「刚接上的那个东西，和界面里的连接器不是一回事」，比先讲分层有效。讲法依据：[MCP 与 WorkBuddy 连接器的区别](https://www.doubao.com/thread/xrWP0PZw2j4F6Qowr)、官方 Connector 文档「自定义连接器」小节。

**① 一句话大白话（逐字上屏）**

> MCP 是一套通用通信标准（协议）；WorkBuddy 连接器是 WorkBuddy 平台里的接入组件。**很多连接器底层是用 MCP 协议实现的，但连接器 ≠ MCP**。

**② 核心区别表（五行，上屏主表）**

| 项目 | MCP | WorkBuddy 连接器 |
|---|---|---|
| 本质 | 通用通信协议标准 | WorkBuddy 平台上的接入组件 |
| 归属 | 开放标准，不属于任何一个产品 | WorkBuddy 平台专属概念 |
| 范围 | Claude、Cursor、各类 Agent 通用 | 只在 WorkBuddy 体系内使用 |
| 包含内容 | 只有通信规则、工具 / 资源模型 | 协议 + 授权管理 + 权限控制 + 平台配置 + 元数据 |
| 关系 | 可被连接器用作底层通信方式 | 是 MCP 的一种宿主落地形态，但不是唯一形态 |

**③ 成对类比（把 4.2 与 4.5 两半并起来再看一次）**

MCP ≈ **USB-C 规范**（电压、通信格式）；连接器 ≈ **一根 USB-C 数据线**（带芯片与认证管理）。数据线基于规范，但它是具体实物，只用来给这台设备接外设。规范可以做出无数根线，线不等于规范。

**④ 完整链路示例（上屏一行）**

`WorkBuddy Agent ↔ WorkBuddy 连接器（MCP 实现）↔ MCP 协议 ↔ 外部 MCP 服务端 ↔ 腾讯文档 / 邮箱等系统`

**⑤ 三个常见误区（投屏，逐条纠）**

1. 误区「MCP 就是 WorkBuddy 连接器」→ 纠正：MCP 是标准；连接器是 WorkBuddy 里的集成单元，**部分连接器底层用 MCP，还有一部分是 Skill + CLI 型，不走 MCP**。
2. 误区「所有 MCP 都是在 WorkBuddy 里用」→ 纠正：MCP 是独立开放协议，脱离 WorkBuddy 照样跑（回扣 4.2 ②）。
3. 误区「连接器总是包着 MCP」→ 纠正：连接器是产品层封装，协议只是其中一种底层实现方式；官方「自定义连接器」本质是安装自定义 MCP 服务，正好说明二者在同一入口相遇，但仍不是同一个东西。

**⑥ 极简记忆版（板书收口）**

MCP = **通用接口规范（语言）**；WorkBuddy 连接器 = **WorkBuddy 里的对接插件**（用这个语言来对接，也可以用别的方式对接）。收口一句：协议管怎么接，连接器管接什么和能不能接。

**⑦ 产品层多做六件事（沿用，压缩带过）**：授权与登录／启用与关闭开关／连接状态与失效重连卡片／独立授权与最小权限／界面可见可管理／失败时的提示与重试。对照 4.3 的三句板书念一遍即可，明细放到 §五 5.0 带练。

**⑧ 官方两处印证与三条边界**

- 官方印证：腾讯乐享授权确认页写「通过乐享知识库 MCP」；连接器管理页右上「自定义连接器」本质是安装自定义 MCP 服务（官方：配置方式与 MCP 配置类似）。4.3 实验里那段配置走的正是同一个入口。
- 边界一：**不是所有连接器都走 MCP**。官方两种实现形态——MCP + CLI（标准化协议）与 Skill + CLI（内置脚本）；后者不走 MCP，二者在数据收集与权限边界上遵循一致原则。
- 边界二：**MCP 是行业开放标准**，不专属某一家产品；课堂不展开厂商、版本与年份考据。
- 边界三：**学生不用会配**。本场由讲师演示接入，学生只看现象、填记录卡；不写代码、不装服务、不管凭据。

> 收口：随后进 4.5 讲连接器本身，再进 §五 把这些开关与授权带练一遍。

### 4.5 连接器是什么：按官方文档讲（6'，压缩讲）

**① 官方定义（原文，逐字上屏）**

> 连接器用于将 WorkBuddy 与外部服务对接，将外部数据和能力引入 AI 工作流。通过配置连接器，您可以让 WorkBuddy 在获得授权后访问和操作第三方服务，实现数据互通与能力扩展。

拆成三句人话：**一端是 WorkBuddy 的 AI 工作流，一端是外部服务，中间那道门是授权**。没有授权，就没有通道。再点一次官方用词「访问和操作」：它既能读，也能按指令去外部服务里做事。

**② 定位（本次重编补齐）**

连接器是 **WorkBuddy 平台内的集成载体 / 接入组件**，是 WorkBuddy 里的东西。它把外部系统封装好，管理授权、权限与连接配置，交给 WorkBuddy Agent 调用；界面上点「添加连接器 → 授权」，操作的就是它。它绑定平台，脱离 WorkBuddy 就没有这个概念，与 4.2 ② 正好相对。

**③ 成对类比的后半**

一根 **USB-C 数据线**：带芯片与认证管理，基于 USB-C 规范，但它是一个具体实物，只用来给设备接入外设。规范（MCP）在前，线（连接器）在后；线基于规范，规范不等于线。

**④ 两种实现形态（官方 + 参考内容，讲清「不是所有连接器都走 MCP」）**

| 形态 | 底层 | 官方措辞 |
|---|---|---|
| MCP 型连接器 | 走 MCP 协议（主流） | MCP + CLI（标准化协议） |
| CLI 型连接器 | 不走 MCP，内置脚本直接调用命令行程序对接外部服务 | Skill + CLI（内置脚本） |

二者在数据收集与权限边界上遵循一致原则。4.3 接入的那段配置，属于前一种形态里的协议层。

**⑤ 平台侧多出来的能力（参考内容）**

认证与授权、权限控制、元信息、工具过滤、启用与关闭、状态与失效重连、界面上可见可管理。协议只规定通信，这些都在平台侧。

**⑥ 官方补充两句（原文要点，不展开）**

1. 当前已支持 **QQ 邮箱、腾讯文档、腾讯乐享、腾讯会议、TAPD、腾讯网盘**等连接器，同时支持**自定义连接器**；**新增连接器后，相关隐私协议条款将同步更新**。
2. 课堂用的**腾讯问卷连接器**是会话内官方连接器插件，**不在上面这张内置清单里**；授权方式以现场页面提示为准。两张清单分开讲。

**⑦ 连接器能做什么（官方表格，四列照抄 + 本场对应动作）**

| 场景 | 官方说明 | 官方示例 | 本场对应动作 |
|---|---|---|---|
| 数据查询 | 从外部数据源获取信息 | 查询数据库、检索文档 | 检索官方素材文档、读取方案 |
| 服务调用 | 调用第三方 API 完成操作 | 发送邮件、创建日程 | **通过腾讯问卷连接器创建在线问卷、回读结构、改单题（本场重点）** |
| 文件管理 | 访问云端存储与文件系统 | 读取网盘文件、上传附件 | 读取方案文件、官方图片 |
| 消息通知 | 与即时通讯工具集成 | 发送企业微信 / 飞书消息 | 把投放链接交到后续物料 |

官方原文一句：「通过连接器，WorkBuddy 可以在任务中调用外部服务的能力，完成数据查询、服务调用、文件管理和消息通知等操作。」

**⑧ 口径修正（沿用重编结论）**

官方没有「双向通道」这个说法。按官方口径讲成一句：**接入是引入，写入要下指令**。依据两处：四类能力里的「**服务调用**」＝调用第三方 API 完成操作，本身包含写；「信息收集与使用」把**用户写入数据**单列一类，**非必要，需您明确指令确认**。创建问卷就是一次「用户写入数据」，必须由学员明确说出「创建问卷」。这条同时是课堂纪律的依据。

**⑨ 本段不讲什么**：一次性粘贴 vs 持续在场、配置与使用全生命周期、信息收集与权限边界三块，页面留在 P10–P12，讲解放到 §五 5.0 / 5.0.1 带练段，跟着授权、启用、创建问卷的动作一起讲。原理段只负责把「连接器是什么、能做什么」立住，30 分钟因此装得下 MCP 与实验。

**J. 一次性粘贴 vs 持续在场（原 §4.3 对比表，五行）**

| 对比项 | 复制文字进对话框 / 单次上传 | 连接器建通道 |
|---|---|---|
| 材料在哪 | 只在这一条消息里 | 整个任务期间持续在场 |

**现场演示**：接入方案文件 → 创建 B 版问卷 → 改方案里的时间 → 用 `update_question` 更新问卷里那道时间题 → 在线问卷跟着变。这是本场最直观的一击，也是题目文档点名的常见坑（学生直接把方案文字复制进对话框，以为这就是连接器）。

**A. 添加连接器（官方 4 步）**
侧边栏「专家·技能·连接器」→ 选中「连接器」页签进入管理页 → 找到需要的连接器，点卡片右上 `+` → 按页面提示完成登录、授权或其他配置 → 完成后即可使用。腾讯问卷连接器需扫码 / 登录授权，**课前必须完成**。

**B. 使用连接器（官方三种方式，原文口径）**

1. **从连接器页面发起对话**：管理页找到已授权的连接器，点卡片右上「去对话」，即可直接开始使用。
2. **创建任务时启用**：新建任务时点输入框左下 `+` > 连接器，在弹窗中开启需要使用的连接器；尚未完成授权的，先完成授权才能使用。
3. **执行任务时按需连接**：任务执行中需要使用尚未连接的连接器时，输入框上方会自动显示连接引导卡片；点击卡片完成授权后，**WorkBuddy 自动继续执行当前任务，无需重新发起对话**。

**C. 授权页上会看到什么（官方使用示例，投屏截图）**

| 官方示例 | 学员会看到的 | 教学落点 |
|---|---|---|
| QQ 邮箱 | 扫码授权 → 手机端确认权限清单：账号信息 / 读取收件箱内近一个月邮件 / 代为发送邮件 / 删除邮件（可选）→ 同意授权 → 卡片名称旁出现**绿色圆点**、右侧出现「去对话」 | 授权不是点一下「同意」，是看清一份权限清单 |
| 腾讯乐享 | 授权确认页写明「通过乐享知识库 MCP」将能：按你拥有的权限访问知识库 / 搜索查询内容 / 协助创建与管理内容 → 微信或手机号登录 → 确认账号信息与权限 → 继续 | 「不超出已有权限范围」在授权页上是看得见的 |

官方提示：QQ 邮箱授权成功时要点浏览器弹窗中的「打开」完成连接，**取消或直接关闭网页可能导致操作中断，需要重新配置连接器**；不同连接器的连接与授权方式可能不同，其他以实际页面提示为准。

**D. 授权失效后重新连接（官方 4 步 + 提示）**
出现「连接器需要重新连接」卡片（提示「此连接器的授权已失效，请重新连接以继续当前任务」）→ 点「重新连接」，按该连接器已有的授权方式完成登录、扫码或授权 → 授权成功后卡片显示已连接，**WorkBuddy 自动重试刚才失败的那一步，无需重新发起对话** → 不想重连可点卡片右上关闭按钮，此时不重试，任务需完成重连后才能继续使用该连接器；失败时提示「连接失败，请重试。」，可再次点击重新连接。

> **官方提示（易考易错）**：只有连接器明确返回**授权失效**时才会出现这张卡片；**网络超时、服务异常或没有权限不会提示重新连接**；同一步骤重新连接后**只会自动重试一次**；也可在对话里主动说「重新连接企业微信」。

**E. 停止使用 / 解绑 / 对话管理（官方三节）**

- **停止使用**：只想让某个连接器不再参与任务 → 输入框左下 `+` > 连接器 → 弹窗中关闭对应连接器的启用状态。
- **解绑**：管理页选中已连接且需解绑的连接器 → 弹窗点「解绑」→ 系统提示已解绑并恢复为未连接状态。
- **通过对话管理**（官方，自然语言）：说「帮我安装 QQ 邮箱连接器」即可引导安装；问「我安装了哪些连接器」会列出已安装及状态，**「已授权但当前关闭」的也会列出，它们平时不参与任务、容易被遗忘**；明确要求卸载时弹出确认窗口，列出即将移除的连接器与数量，确认后完成卸载，**内置连接器不支持卸载**。

**F. 自定义连接器（官方）**
管理页右上角「自定义连接器」按钮 → 安装自定义 MCP 服务，配置方式与 MCP 配置类似。**4.3 的公共 MCP 接入实验走的正是这个入口**，课堂上由讲师演示一次即可，学员不配置、不写代码、不装服务。

**G. 接上之后会读写什么（官方「信息收集与使用」表，逐行上屏）**

| 收集项 | 类型 | 官方用途 |
|---|---|---|
| 第三方账号标识 | 必要 | 邮箱地址、账号 ID 等，用于在第三方服务中识别身份 |
| 授权凭据 | 必要 | OAuth Access / Refresh Token，或手动填写的 API 密钥 |
| 第三方业务数据 | 必要 | **仅在您的指令触发时按需读取**（邮件、文档、知识库、会议、TAPD 项目数据等） |
| 用户写入数据 | 非必要 | 代发邮件、创建 / 编辑文档、创建会议等，**需您明确指令确认** |

这张表是「基础讲解」里最该讲清的一页：学生关心的不是接口，是**接了之后我的数据会怎样**。G 与 4.5④ 的口径修正正好互相印证。

**H. 权限边界三条（官方原文）**：每个连接器独立授权 / 不主动定时抓取 / 不超出您已有权限范围。

**I. 注意事项四条（官方，压缩成四句）**

- **安全提示**：授权信息要确保正确；授权后可随时通过开关禁用或断开；建议定期检查连接器状态。
- **积分提醒**：**连接器自身的读写不消耗积分**；WorkBuddy 对**外部数据**进行理解、汇总时会消耗积分。
- **第三方共享与免责**：本质是「与第三方服务交互」，凭据由 WorkBuddy 维护以便代为调用；自定义连接器的访问范围由配置决定，WorkBuddy 不预设范围，启用前审慎评估。
- **使用建议**：调用产生的访问、读写、消息发送**均以你本人身份与授权范围执行**，涉及对外发送、内容修改前再次确认目标对象与内容；第三方服务异常优先查看该服务状态与协议；API 密钥与 Token 妥善保管，不再使用的连接器及时撤销授权。

**课堂纪律由 G / H / I 直接推出**：创建问卷属于「用户写入数据」，需明确指令；发布投放链接、修改已发布内容前再确认一次；A 版链接不外发、课后清理测试问卷。

### 5.1 接入什么

| 材料 | 来源 | 接入方式 | 用在问卷哪里 |
|---|---|---|---|
| 第 2 节活动策划方案 | 本组产出② | 本地文件 / 腾讯文档 | 问卷标题、欢迎语里的时间地点、报名区字段 |
| 三个活动亮点 | 方案第 5 项物料清单 | 同上 | 「现场最想玩什么」多选题的选项 |
| 目标人群描述 | 方案第 3 项 | 同上 | 参加人数、到场时段两题的选项 |
| 官方名称与素材调性 | 游戏官网 / 官方素材包 | 图片文件 / 文档检索 | 问卷标题、欢迎语措辞、IP 名称不写错 |

> **边界提醒**：腾讯问卷的视觉样式由平台模板决定，官方海报 / 角色图不等于能直接贴进问卷。素材的作用是让**文字信息**准确、调性一致，不强求配色还原。这条正好用来讲「连接器能接材料，但目标平台能呈现什么由平台决定」。

### 5.2 演示顺序

1. **授权**〔对照 A · 工具清单前后对比〕：先不启用，问一句「你现在能创建一份线上问卷吗」并投屏回答（只能给一段问卷文本）；再完成腾讯问卷连接器登录，确认卡片显示已连接状态，用**同一句话**再问一次（可以真的建出来）。课前先做一遍，现场只复核。
2. **启用**：创建任务时用方式②（输入框左下 `+` > 连接器）挂上腾讯问卷连接器；方案文件与官方素材同时作为上下文接入。
3. **写问卷描述**：用纯文本 DSL 写出问卷标题 + 引导语 + 8–10 道题（语法见 5.2.1）。
4. **创建并取回链接**：连接器调用 `create_survey` → 返回 `survey_id` 与 `hash` → 拼出投放链接 `https://wj.qq.com/s2/{survey_id}/{hash}`，当场打开验证。
5. **回读与改单题**：`get_survey` 确认题目结构 → `update_question` 改一道题 → 再回读一次，说明「改的是线上那份，不是本地文件」。
6. **方式③ / 对照 B · 断开再问**：任务内关闭该连接器的启用状态，再问「把刚才那份问卷加上一道题」，投屏看它从「能改线上那份」变成「只能给你一段文本」；随后重新启用，演示引导卡片与自动继续。两个对照共用同一次演示，不额外占时。

### 5.3 常见坑（讲师巡场重点）

| 坑 | 表现 | 处置 |
|---|---|---|
| 把复制粘贴当连接器 | 方案文字贴进输入框，输出仍会跑偏 | 回看 5.0.1 的「改方案 → 更新问卷」演示 |
| 授权没走完 | 卡在扫码 / 登录页，`create_survey` 报未授权 | 课前统一授权，现场确认已连接状态 |
| 以为连接器只能读 | 只敢让它读文件，最后手工去问卷后台建表 | 明确点出「服务调用」这一类能力 |
| 官方图片当成能贴进问卷 | 花时间调配色、找头图 | 说明平台样式边界，素材只管文字信息 |
| DSL 格式写错 | 题目内空行、选项带字母前缀 → 创建失败 | 按 5.2.1 骨架写，课前验证语法 |
| 反复重建问卷 | 每改一次就 `create_survey`，留下一堆重复问卷 | 改单题用 `update_question`；A 版标「测试·勿投放」 |
| 授权失效 | 执行中断在半路 | 认「重新连接」卡片，不重开任务 |
| 和 Skill 混用 | 以为接了材料就能自动按规格出题 | 材料归连接器，题目结构归流程，本场只练材料 |

## 六、`70-105'` 上手实操（35 分钟）

**任务**：同一个需求「做一份本组活动的报名问卷」，两版都通过腾讯问卷连接器创建真实在线问卷，对比后定稿正式版投放链接。

| 步骤 | 动作 | 时间 |
|---|---|---|
| A 版 | 断开所有材料，用连接器创建一版（标题标「测试·勿投放」） | 8' |
| 接入 | 挂载方案文件 + 官方素材包，确认腾讯问卷连接器已连接 | 7' |
| B 版 | 接入材料后创建正式版，取回投放链接并当场打开 | 10' |
| 对比 | 四行对比 + `get_survey` 回读两版结构 | 6' |

## 七、产出③规格与合格线

**腾讯问卷在线报名问卷**，8–10 题，四类题型齐全：

| 题型 | 示例 | 问卷题型 | 信息必须来自 |
|---|---|---|---|
| 基本信息 | 姓名、手机、所在城市 | 单行文本题 | — |
| 报名意向 | 参加人数、偏好时间段 | 单选题 | 方案的活动流程 / 目标人群 |
| 需求调研 | 想看什么环节、想要什么周边 | 多选题 | 方案的三个活动亮点 |
| 开放题 | 对活动的期待 / 建议 1–2 题 | 多行文本题 | — |

**交付三件**：

1. 正式版投放链接 `https://wj.qq.com/s2/{survey_id}/{hash}`（当场可打开、可填写）
2. **素材接入记录**：一张表写清「材料 / 来自哪里 / 通过什么接入 / 用在了问卷哪里」+ A / B 两版链接 + 四行对比 + 一句话结论
3. **问卷纯文本描述**（DSL 存档，便于复现与改单题）

**合格线**：

- [ ] 问卷信息与第 2 节方案一致（标题、时间、地点、亮点对得上）
- [ ] 8–10 题，题型多样，不重复不诱导，且**通过腾讯问卷连接器创建**（有投放链接与 `survey_id`）
- [ ] 使用记录写清「材料通过连接器进入工作流、持续在场；成果通过腾讯问卷连接器写入外部服务」
- [ ] 能对比出「接材料」与「凭空生成」两版的质量差异，并给出正式版投放链接

> **口径校准**：样例 `03-素材接入记录.md` 自检清单原写「题目 6 道」、且以 `03-报名问卷.html` 为交付物。现统一为 **8–10 题 + 腾讯问卷在线问卷**；样例 HTML 保留作**内容示意**，不是课堂交付形态。样例已同步标注。

**讲师点评要点**：现场做一次「断开材料创建 / 接入材料创建」的对比，差异最直观；点评只抓「信息对不对得上方案、链接能不能真的发出去」，不评平台皮肤。

## 八、与相邻概念的边界（贯穿全场，不单独成段）

| 概念 | 管什么 | 本场怎么讲 |
|---|---|---|
| 上传文件 / `@` 引用 | 一次性上下文 | 5.0.1 对比表，作为对照物 |
| 连接器（数据引入） | 外部数据和能力进入工作流 | 官方定义；读方案、读官方素材 |
| 连接器（服务调用 / 用户写入数据） | 成果写到哪去 | 腾讯问卷连接器建出在线问卷；需明确指令确认 |
| Skill | 事情按什么流程做 | 只点名，不展开（第 2 场已讲） |
| 专家 | 用什么专业眼光做 | 只点名，不展开（第 4 场讲） |
| 资料库 | 资料集中管理与检索 | 只提一句，与外部服务通道区分 |
| MCP | 开放通用协议标准，不属于任何产品 | 4.2 先讲清定义、定位与归属、协议组成与三种角色，4.3 做公共 MCP 接入实验，4.4 再点破「MCP ≠ 连接器」并讲清区别；学生不写代码 |

板书收口：**MCP 是通用规范，连接器是 WorkBuddy 里的那根线；两者不是同一个东西**。MCP 把工具挂上来，连接器把授权、状态和边界管起来；外部数据与能力由此进入工作流，要往外部服务写东西，还得有授权和明确指令。万能公式的完整整合留到第 4 场，本场不提前收。

## 十、讲法边界与常见坑

- 只讲「会用、懂边界」。**MCP 在 4.2 讲清定义、开放标准的定位与归属、USB-C 规范类比、协议三部分组成、四项价值与三种角色，4.3 由讲师现场接入一个公共 MCP，4.4 再用一句话、五行区别表、完整链路与三条误区点破「MCP ≠ 连接器」**；不讲协议报文、SDK、版本号、API Key / Token 管理，不做自定义 MCP 服务开发。公共 MCP 实验由讲师配置，学生只观察、填记录卡。
- **基础讲解以官方 Connector 文档的小节名称与原文措辞为准**（4.5 / 5.0.1），不自造「双向通道」「桥梁」这类口径；写入侧按官方「服务调用」+「用户写入数据需明确指令确认」来讲。
- **两张清单分开讲**：官方内置连接器（QQ 邮箱、腾讯文档、腾讯乐享、腾讯会议、TAPD、腾讯网盘等）与课堂用的腾讯问卷连接器插件不混为一张；授权方式以现场页面提示为准。
- 不把「授权」讲成一个按钮：官方使用示例里要看清权限清单，授权成功后还要点浏览器弹窗的「打开」，否则可能中断。
- MCP 关系段放在实验之后讲，用**成对类比**收口（USB-C 规范 / 一根 USB-C 数据线），不讲成技术标准编年史、不做厂商与年份考据；学生只需记住「MCP 是通用规范，连接器是 WorkBuddy 里的对接插件，两者不是同一个东西；协议管怎么接，连接器管接什么和能不能接」。
- **归属与范围必须讲清**：MCP 是开放标准、不属于任何产品、脱离 WorkBuddy 照样跑；连接器是 WorkBuddy 平台专属。两种实现形态要明说「MCP 型走协议、Skill + CLI 型不走 MCP」，不能讲成所有连接器都包着 MCP。
- 公共 MCP 实验只接只读、免密钥、免账号的公开服务；不接需要 WebHook / Token 或能对外发消息的服务，课前跑通、课后清理，网络不通时放录屏，不现场排错。
- 腾讯问卷只讲三个动作：创建、回读、改单题；不讲后台全部功能与回收数据分析（后者属第 6 场）。
- 不把连接器讲成「上传文件按钮」，也不讲成「更高级的 Skill」。
- 不做跨场回溯、不提前收口万能公式；本场只埋「连接器管材料，也管把成果写出去」这一句。
- 常见坑：原理段讲成产品功能罗列；演示段只点不练；实操段学生跳过 A 版直接做 B 版（对比就没了）；把测试版链接发出去；反复 `create_survey` 留下一堆重复问卷。
- 官方界面、按钮名与 DSL 题型标记以现场版本为准，课前按实际界面截图核对。
