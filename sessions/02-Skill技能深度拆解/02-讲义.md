| 维度   | 目标                                                    |
| ---- | ----------------------------------------------------- |
| 知识目标 | 说清 Skill 的定义与出现背景；掌握 Skill 的三要素（标准工作流程 + 任务脚本 + 输出规范） |
| 能力目标 | 能判断写方案这类场景该找什么 Skill；看懂一个 Skill 的内部结构；具备改造 Skill 的意识       |

> **两条执行铁律**（本场反复强调）：
> 1. **不指定 Skill，让学生自己想办法找**——讲到"用 Skill 写方案"时只讲找法与判断标准，不报具体工具名；学生自行到技能市场/内置能力里挑一个能用的，挑不出来本身就是一次真实选型训练。
> 2. **举例贴近软件人视角**——方案结构用"需求背景 → 目标（可量化）→ 目标受众 → 流程 → 场地/物料 → 预算 → 风险 → 验收标准"来讲，学生可类比自己熟悉的 PRD / 项目策划案。

## 四、授课段详细设计（0-60'）

### 0-8'　复盘与答疑

- **目标**：承接第 1 场，把注意力收拢到本场主线。
- **要点**：点评上一场的**组队宣讲 PPT / 活动海报**（第 1 节产出）；收集疑问；抛出主线问题——**"设计到底靠灵感，还是靠流程？"**
- **讲法提示**：不急着回答这个问题，留到 20-33' 用输出差异来回答。顺势点出本节任务——"把你们宣讲里那个活动想法，写成一份能落地的方案"。

### 8-20'　Skill 发展史（定义 + 必要性）

- **目标**：先讲清"为什么会有 Skill"，再讲"它是什么"，让学生理解其必然性。
- **内容要点**：
  - 三代演进（讲师话术参考）：
    - **第一代·对话式 AI**：一问一答，输出随机，每次都要重新描述需求，好结果无法沉淀。
    - **第二代·提示词技巧**：靠写长提示词换取好输出，但提示词散落在个人笔记里，难复用、难协作。
    - **第三代·Skill 技能**：把"流程 + 脚本 + 规范"打包固化，一键调用，输出稳定、可复用、可迭代。
  - **定义**：Skill = 把一套标准化的专业工作流程封装成可复用的 AI 能力包。
  - **必要性**：设计的价值不只在于灵感，更在于可复现的专业工序。Skill 让"好方法"留得下来、传得出去。
- **讲法提示**：用学生熟悉的场景类比——"就像软件团队的 PRD 模板 / 设计系的 VI 手册：把判断固化成标准，新人也能稳定产出"。

### 20-33'　先体验、后拆原理

- **目标**：用输出差异钩住注意力，再顺势拆解原理。
- **内容要点**：
  1. 现场用**同一个活动想法**跑两遍：一版"裸聊"（直接对话，让它写活动策划方案），一版调用一个 Skill 写同一活动。
  2. 并排展示两版输出，让学生先说差异——重点看**8 项齐不齐、目标能不能量化**。
  3. 顺势拆出公式：**Skill = 标准工作流程 + 任务脚本 + 输出规范**。
  4. 破除误解："Skill 不是按钮，按钮背后是一整套被写好的专业判断。"
- **讲法提示**：**这里不展开讲"用的哪个 Skill"**，学生会追问名字时统一回答——"等下你们自己去技能市场找，能找到几个算几个，这正是本节要练的"。差异要"看得见"：裸聊版通常漏项、目标写虚词，Skill 版 8 项齐全、目标带数字，对比一目了然。

### 33-45'　写方案场景的 Skill 选型（怎么找）

- **目标**：从"有哪些 Skill"转向"写方案这类活该找什么、怎么判断"。**这一节讲的是找法，不是发名单。**
- **内容要点**：聚焦"写方案"这一类任务讲判断标准；市场上同类 Skill 很多、会变动，不要求学生记名字。以下推荐来自《设计类学生常用 skill 列表》（WorkBuddy 在线 Page），名称按平台实际展示填写，仅作讲师演示与兜底参考。

**① 写方案的选型判断（先讲逻辑，不指定具体 Skill）**

| 场景 | 找什么方向的 Skill | 判断标准 |
| --- | --- | --- |
| 把活动想法展开成完整方案 | 文档/策划/方案生成类 Skill（内置文档能力也可） | 能不能按结构输出、8 项齐不齐、目标是否可量化 |
| 方案配图 / 主视觉草图 | 海报/平面生成类 Skill | 要不要出图、中文文字是否稳定 |
| 方案整理成汇报材料 | PPT / 思维导图 / Word 内置能力 | 框架先行、逻辑统一、开箱即用 |

- **找 Skill 的动作**（现场带学生走一遍）：进技能市场 → 搜"策划""方案""文档""PRD"等关键词 → 看描述里有没有"结构化输出/按章节生成" → 装一个试跑。找不到合适的，用内置文档能力兜底，**不要用"没有 Skill"当借口跳过对比**。

### 45-55'　Skill 制作方法论

- **目标**：让学生理解 Skill 是可被设计、可被优化的产物，并掌握一条自己就能上手的路子。
- **核心路径**：**从已有工作流提取 → 按四步法固化 → 用最佳实践打磨**。强调"不用凭空想 Skill，你重复做的事就是素材"。
- **讲法提示**：这一段是"Skill 怎么造"的知识讲授，**不是本节任务**——本节任务是"用 Skill 写方案"。但要讲，因为学生需要看懂 Skill 内部结构才能判断找到的 Skill 好不好用。

#### ⓪ 先看清三条路：Skill 从哪来（2-3 分钟带过）

| 路径 | 做法 | 优点 | 短板 | 适合 |
|---|---|---|---|---|
| **人工技能编排**（SOP 编码 / 流程脚本化） | 专家口述 SOP、判断分支、边界情况，写成系统提示词 + 分支判断 + 工具调用顺序 | 可控、可审计、出错好改，稳定性最高 | 费人，隐性经验难写全，判断一多维护就吃力 | 单据审核、固定报表、工单处理等标准流程 |
| **工具封装 + 能力绑定**（偏工程层） | 把人本来就在用的软件、接口、脚本封装成可调用工具，再配上触发条件。例：对账 = 查数据库 + 跑表格宏 + 发消息，封成 3 个工具组成技能 | 不复用人的思考，复用人的工具链路 | 依赖系统本身可被集成 | 强系统集成场景 |
| **逆向观察萃取**（与技能蒸馏同源） | 从操作日志、录屏、操作回放、对话记录里挖高频动作、前置与后继条件，自动生成 SOP 或调用序列 | 不需要专家主动口述，存量数据越多越好用 | 日志不记录内心判断，容易只学到表面动作 | 专家没空配合、历史数据充足 |

- **取舍**：前两条靠人把流程交出来，第三条靠数据把流程挖出来。**本课走第一条**——设计任务的隐性判断多、系统集成少、历史操作日志基本没有，人工编排是唯一切实可行的路。
- **讲法提示**：这段不展开，只给学生一个坐标——Skill 不是只能靠大厂数据训练出来，你自己把流程口述清楚就能做一个。

#### ① 入口：工作流提取法（重点讲）

把自己反复做的工作剥离成 Skill，是最实用、最容易成功的路径。判断一件事值不值得提取，看三条：

| 判断标准 | 说明 | 活动/软件场景举例（贴软件人视角） |
| --- | --- | --- |
| 高频重复 | 每周/每个项目都要做 | 每场活动都要写方案（≈每次迭代都要写需求文档） |
| 套路稳定 | 步骤大同小异，不是每次都从头想 | 方案框架固定、只换游戏（≈PRD 模板固定，只换项目） |
| 输出可标准化 | 有明确的好/坏、合格/不合格标准 | 8 项齐不齐、目标是否可量化（≈验收标准能不能被逐条核对） |

**工作流提取四问**（让学生现场套用）：

1. 我最近反复在做的是哪件事？
2. 每次做它的步骤是不是差不多？
3. 哪一步我最依赖个人经验、或最容易出错？——**这就是最该写进 Skill 的部分**
4. 什么样的结果算"合格"？——把它写成检查项

#### ② 方法：四步法固化

**拆任务 → 定流程 → 写脚本 → 设输出规范**。以**「活动策划方案 Skill」**为例（结构可直接类比 PRD / 项目策划案）：

| 步骤 | 要做的事 | 活动方案示例 |
| --- | --- | --- |
| 拆任务 | 把模糊需求拆成明确子任务 | 拆成 8 项：背景 → 目标 → 目标受众 → 流程 → 场地/物料 → 预算 → 风险 → 验收标准 |
| 定流程 | 规定子任务的执行顺序与依赖 | 先定目标受众再写流程、先事实后预算 |
| 写脚本 | 为每个子任务写清执行指令 | "目标须含可量化指标，如招募 200 人、满意度 ≥ 4.2/5" |
| 设输出规范 | 规定格式、篇幅、语气、检查项 | 8 项齐全、小标题统一、末尾自检"目标可量化了吗、物料清单具体吗" |

#### ③ 最佳实践（讲 2-3 条，其余发口诀卡）

| 实践            | 做法                            | 为什么重要                  |
| ------------- | ----------------------------- | ---------------------- |
| **先手工跑通再固化**  | 先把流程手动做 2-3 遍，确认步骤稳定再写 Skill  | 没验证过的流程写进 Skill 只会稳定地错 |
| **隐性经验显性化**   | 把"怎么判断目标够不够具体""什么算合格"写成文字  | 这一步最难也最值钱，Skill 的价值全在这 |
| **描述决定命中率**   | 触发描述写全用户的真实说法（含口语），并注明"不适用情形" | 否则 AI 在该用的时候想不起、不该用时乱用 |
| **渐进披露**      | 正文只写骨架，详细规范/参考放资源文件，用到才加载     | 保证 AI 读得完、读得准          |
| **写"常见错误"清单** | 把自己踩过的坑写进去                    | 让 AI 少犯你已经犯过的错         |
| **故意演砸验证**    | 做完后用边缘说法测试，不命中就补触发词           | 命中率是 Skill 能不能用的生死线    |

- **讲法提示**：这是本场"思维含金量"最高的一段。10 分钟有限，**课上重点讲①工作流提取法的四条判断 + 四问，以及③的前两条（先跑通、经验显性化）**，其余发口诀卡课后看。落点一句话——**"你重复做的事，就是你的第一个 Skill"**。

### 55-60'　优化已存在 Skills

- **目标**：建立"我也能定制"的信心，并发布下半场任务。
- **内容要点**：
  - 打开一个**已有 Skill** 的内部结构，现场改一句脚本，展示输出如何随之变化；再用同一套评判口径检验改前与改后。
  - 发布下半场任务与评判口径：用自己找到的 Skill 写活动策划方案；明确时间节点。

## 五、讨论及实践段详细设计（60-120'）

### 60-70'　课堂实践任务发布

- **形式**：各组把自己第 1 节宣讲的活动想法，写成一份**活动策划方案**；两版对照——裸聊版 + Skill 版。
- **交付观**：交付的是"结构完整、目标可量化、能指导下节执行"的方案，不是一段漂亮文案。
- **铁律重申**：**Skill 不指定，各组自己想办法找**——到技能市场搜、看描述判断、装一个试跑；实在找不到用内置文档能力兜底。找不到合适 Skill 的组，讲师只提示搜索关键词，不代劳指定。

**活动策划方案 8 项规格**（投影展示，全程可见）：

| 项 | 内容 | 合格线 |
| --- | --- | --- |
| 1 背景 | 为什么办这场活动、和游戏 IP 的关系 | 有具体由头，不是套话 |
| 2 目标 | 要达成什么 | **含可量化指标**（如招募 200 人、满意度 ≥ 4.2/5） |
| 3 目标受众 | 面向谁 | 具体人群，能指导后续报名问卷设计 |
| 4 流程 | 活动怎么进行 | 分时段、可执行 |
| 5 场地/物料 | 在哪办、要什么物料 | 物料清单能对应第 4 节要做的三件（文案/长图/落地页） |
| 6 预算 | 花多少钱 | 有分项，不是笼统一句 |
| 7 风险 | 可能出什么岔子 | 有预案 |
| 8 验收标准 | 怎么算成功 | 可逐条核对 |

- **评判口径**（投影展示，全程可见）：

| 维度    | 权重  | 判断标准                    |
| ----- | --- | ----------------------- |
| 结构完整度 | 30% | 8 项齐不齐                |
| 专业度   | 30% | 目标可量化、流程可执行          |
| 规范符合度 | 20% | 格式统一、两版差异可追溯         |
| 可复现性  | 20% | 物料清单与第 1 节宣讲 PPT 第 5 页对得上 |

### 70-95'　上手实践

- **两段走**：
  - 70-82'：先用提示词直接跑一遍——把活动想法直接写成方案，拿"裸聊版"输出，留档对照。
  - 82-95'：各组用**自己找到的 Skill** 写同一活动的方案，拿"Skill 版"输出。
- 讲师巡场，**重点纠偏**：只会点按钮、不看输出规范；把 Skill 当搜索框用；不做对比直接交一版；目标写成"让更多人知道"这类无法量化的虚词；物料清单和宣讲对不上。
- 提醒时间节点：95' 进入讨论。

### 95-110'　对比讨论

- 学员对比两版方案，围绕三问讨论：
  1. **8 项齐不齐？**（结构、完整度、稳定性）
  2. **差异由 Skill 的哪部分结构造成？**（对应三要素与四步法）
  3. **方案里的物料清单，与宣讲 PPT 第 5 页对不对得上？**（检验链路一致，不检验"迁移到哪些专业"）

### 110-117'　成果分享

- 学员自愿分享一条关键发现。
- 讲师归纳落点：**Skill = 可复用工序；自己选对场景 + 用好规范 = 结构稳定、不漏项。**

### 117-120'　产出收口

- **当堂任务**：各组定稿活动策划方案（8 项），连同裸聊版一起留存，作为**对比记录**。
- **要求**：按本节 8 项规格整理并命名（`组号-游戏名-活动策划方案`），当堂收齐；未完成的第 3 场开场 10 分钟补齐。

## 六、产出与衔接

- **本场产出** → 活动策划方案（8 项 + 对比记录）
- **下一场衔接**：第 3 场用连接器把本场方案里的**真实信息**（时间、地点、亮点）+ 官方游戏素材接入，做出活动报名问卷。方案是问卷的输入，不是"个人作品素材"。

## 八、设计逻辑说明

- **认知递进**：历史铺垫（为什么）→ 体验先行（看见差异）→ 原理拆解（是什么）→ 方法内化（怎么做）→ 轻改造（我也能做）。
- **弱化步骤、强化思维**：全程不逐条讲操作按钮，而是围绕"功能搭配思维"展开。
- **评图式讨论**：沿用设计专业熟悉的"对比—点评—归纳"方式，让学生从两版输出的差异中自己得出结论，而非被动接收功能清单。
- **任务性质对齐**：本节是"用 Skill 干活"（写方案），不是"造 Skill"；造 Skill 的方法作为知识讲授保留，为后续独立实践打底。

## 九、来源说明与课前核对

- **Skill 来源已定**：全部使用 **WorkBuddy 平台提供的 Skill**（市场安装 + 内置能力两类），不预制、不自建。
- **推荐依据**：《设计类学生常用 skill 列表》（WorkBuddy 在线 Page，链接见文末），已按场景收录至 33-45' 工具地图，名称按平台实际展示填写。
- **课前必做**：
  1. 在市场里搜"策划/方案/文档/PRD"实测一遍，确认至少 1 个写方案类 Skill 可安装可用，**作为兜底**——但不指定给学生，让学生自己搜；
  2. 确认其中 1 个可展示内部结构、可现场改脚本，供 55-60' 演示；
  3. 内置能力（ImageGen / 图片处理 / PPT / 思维导图 / Word）开箱即用，作为找不到 Skill 时的兜底。
- **风险提示**：市场 Skill 的安装状态、可用模型（如 AI Hive 下的 GPT Image 2 / Nano Banana）可能变动，开课前实测一遍；若演示 Skill 临时不可用，切到内置能力兜底。课堂重点是**选型逻辑与结构判断**——本节考的是"能不能找到并用一个 Skill 写出结构稳定的方案"，不是记住某个 Skill 名。
