## 四、授课段详细设计（0-60'）

### 0-8'　复盘与答疑

- **目标**：承接第 1 场，把注意力收拢到本场主线。
- **要点**：点评上一场的**组队宣讲 PPT / 活动海报**（第 1 节产出）；收集疑问；抛出主线问题：**"设计到底靠灵感，还是靠流程？"**
- **讲法提示**：不急着回答这个问题，留到 20-33' 用输出差异来回答。顺势点出本节任务："把你们宣讲里那个活动想法，写成一份能落地的方案"。

### 8-20'　Skill 发展史（定义 + 必要性 + 工作方式）

- **目标**：先讲清"为什么会有 Skill"，再讲"它是什么、怎么起作用"。
- **内容要点**：
  - Skill 发展历程（讲师话术参考）：
    - **第一代·对话式 AI**：一问一答，每次都要重新描述需求，好结果留不下来。
    - **第二代·提示词技巧**：靠写长提示词换取好输出，但提示词散落在个人笔记里，每次要手动复制粘贴，难复用、难协作。
    - **第三代·Skill 技能**：把流程、指令、规范打包成一个文件夹，AI 根据任务自己判断要不要用，也可以手动指定；输出更稳定，可复用、可迭代。
  - **定义**：Skill = 把一套标准化的专业工作流程封装成可复用的 AI 能力包。
  - **工作方式**（和"存起来的长提示词"的区别就在这里）：
    1. **按描述触发**：每个 Skill 都有一段描述，写明"做什么、什么时候用"。AI 平时只看这段描述，判断当前任务对得上才启用。
    2. **用到才加载**：启用后才读取完整指令，参考资料、模板、脚本再按需读取。装很多个 Skill 也不会把 AI 的注意力撑满。
  - **必要性**：设计的价值不只在于灵感，也在于可复现的专业流程。Skill 让好方法留得下来、传得出去。
- **讲法提示**：类比用一个就够，用 **VI 手册**："把审美判断固化成标准，新人照着做也能稳定产出"。定义页不再重复这个类比。讲"输出更稳定"时说清分寸：Skill 能明显减少漏项和格式走样，但大模型每次输出仍有差异，所以最后还要人检查。
- **官方出处**（定义页展示）：
  - Anthropic 工程博客 *Equipping agents for the real world with Agent Skills*（Agent Skills 的设计说明，含"渐进披露"机制）
  - 规范站 agentskills.io（Agent Skills 开放规范）
  - 示例仓库 github.com/anthropics/skills（示例 Skill、规范与模板）
  - 说明：以上是 Agent Skills 规范的出处。WorkBuddy 中 Skill 的文件结构与该规范的对应关系，课前按平台实际版本核对后再讲（见第九节）。

### 20-33'　先体验、后拆原理

- **目标**：用输出差异钩住注意力，再顺势拆解原理。
- **内容要点**：
  1. **学生体验**：每人拿到同一段会议记录，直接对 AI 说"帮我整理成会议纪要"，**不提任何格式要求**。
  2. 收几份学生的版本并排展示，让学生自己说差异：有人分了议题、有人只写结论；有人列了待办、有人没写负责人和截止时间。抛出问题：**怎样让每个人、每一次都得到结构一致、不漏项的会议纪要？**
  3. 讲师再用会议纪要 Skill 跑同一段记录，展示结构固定、不漏项的结果，顺势拆出公式：**Skill = 标准工作流程 + 任务指令 + 输出规范**。
  4. 打开这个 Skill 的文件夹，指出三要素各写在哪里：

| 三要素 | 在 Skill 里的位置（以 Agent Skills 规范为例） |
| --- | --- |
| 标准工作流程 | `SKILL.md` 正文里的步骤说明 |
| 任务指令 | `SKILL.md` 正文里每一步的具体要求；需要执行代码的部分放在 `scripts/` |
| 输出规范 | `SKILL.md` 正文里的格式要求和检查项；较长的模板放在 `assets/` 或 `references/` |
| （触发条件） | `SKILL.md` 开头的 `name` 与 `description` |

- **讲法提示**：**体验刻意选简单例子**：会议纪要人人能做、几秒出结果、版本差异一眼可见。讲师不给格式，让差异自然出现。**写活动策划方案留作本堂实践任务**，这里不提前演示，避免把练习答案先讲掉。学生追问"用的哪个 Skill"时统一回答："等下你们自己去技能市场找，这正是本节要练的"。学生版本常见问题是结构各不相同、漏项、待办没负责人；Skill 版通常 6 项齐全、待办可追踪。如果现场 Skill 版也漏了项，正好借机说明"Skill 减少漏项，但仍要对照输出规范检查"。

### 33-45'　写方案场景的 Skill 选型（怎么找）

- **目标**：从"有哪些 Skill"转向"写方案这类活该找什么、怎么判断"。**这一节讲的是找法，不是发名单。**
- **内容要点**：聚焦"写方案"这一类任务讲判断标准；市场上同类 Skill 很多、会变动，不要求学生记名字。

**① 写方案的选型判断（本节重点，先讲逻辑，不指定具体 Skill）**

| 场景 | 找什么方向的 Skill | 判断标准 |
| --- | --- | --- |
| 把活动想法展开成完整方案 | 文档/策划/方案生成类 Skill（内置文档能力也可） | 能不能按结构输出、8 项齐不齐、目标是否可量化 |
| 方案配图 / 主视觉草图 | 海报/平面生成类 Skill | 要不要出图、中文文字是否稳定 |
| 方案整理成汇报材料 | PPT / 思维导图 / Word 内置能力 | 框架先行、逻辑统一、开箱即用 |

**② 找 Skill 的四个动作**（现场带学生走一遍）

1. 进技能市场，搜"策划""方案""活动""文档"等关键词。
2. 看描述：有没有写"结构化输出/按章节生成"，适用场景是不是写方案。
3. 装一个试跑，用一句话需求看输出结构。
4. 判断能不能改：能打开内部结构、能改输出规范的优先（实践环节要改）。

找不到合适的，用内置文档能力兜底，**不要用"没有 Skill"当借口跳过对比**。

**③ 获取和安装 Skill 的渠道**

| 渠道 | 怎么拿到 | 适合什么情况 |
| --- | --- | --- |
| 内置能力 | 不用安装，能力列表里直接可见 | 图片处理、ImageGen、PPT / 思维导图 / Word |
| 技能市场 | 在平台里搜关键词，一键安装 | 写方案、海报、UI 原型、抠图修图等 |
| 本地导入 | 把 Skill 文件夹放进技能目录 | 别人分享的，或自己改过的 |
| 官方仓库 | github.com/anthropics/skills 下载后导入 | 想拆开看结构、照着写 |
| 自己写 | 按四步法做一个 | 市场上找不到的流程 |

### 45-55'　Skill 制作方法论

- **目标**：让学生理解 Skill 是可被设计、可被优化的产物，并掌握一条自己就能上手的路子。
- **核心路径**：**从已有工作流提取 → 按四步法固化 → 用最佳实践打磨**。强调"不用凭空想 Skill，你重复做的事就是素材"。
- **讲法提示**：这一段是"Skill 怎么造"的知识讲授，**不是本节任务**，本节任务是"用 Skill 写方案"。但要讲，因为学生需要看懂 Skill 内部结构，才能判断找到的 Skill 好不好用、实践里才知道改哪里。
- **10 分钟分配**：⓪ 三种制作方式 1 分钟带过 → ① 工作流提取法 4 分钟 → ② 四步法 4 分钟 → ③ 最佳实践 1 分钟点两条，其余发口诀卡。

#### ⓪ 先看清三条路：Skill 从哪来（1 分钟带过）

| 路径 | 做法 | 优点 | 短板 | 设计场景举例 |
|---|---|---|---|---|
| **人工技能编排**（SOP 编码 / 流程脚本化） | 有经验的人口述 SOP、判断分支、边界情况，写成指令 + 分支判断 + 工具调用顺序 | 可控、出错好改，稳定性最高 | 费人，隐性经验难写全，判断一多维护就吃力 | 写设计说明、检查展板排版规范、审核 VI 应用是否合规 |
| **工具封装 + 能力绑定**（偏工程层） | 把本来就在用的软件、脚本封装成可调用工具，再配上触发条件。例：作品集出图 = 抠图 + 套版式 + 批量导出命名，封成 3 个工具组成技能 | 复用的是工具链路，不需要把判断写清楚 | 依赖软件本身能被调用 | 批量导出切图、按规范命名文件 |
| **逆向观察萃取**（与技能蒸馏同源） | 从操作记录、录屏、对话记录里挖高频动作和前后步骤，自动生成 SOP | 不需要专家主动口述，存量数据越多越好用 | 记录里没有当时的判断理由，容易只学到表面动作 | 有大量历史修改记录、老师没空口述的场景 |

- **取舍**：前两条靠人把流程交出来，第三条靠数据把流程挖出来。**本课走第一条**：设计任务的隐性判断多、要调用的系统少、历史操作记录基本没有，人工编排最可行。
- **讲法提示**：这段不展开，只给学生一个坐标：Skill 不是只能靠大厂数据训练出来，你自己把流程口述清楚就能做一个。

#### ① 入口：工作流提取法（重点讲）

把自己反复做的工作整理成 Skill，是最实用、最容易成功的路径。判断一件事值不值得提取，看三条：

| 判断标准 | 说明 | 设计场景举例 |
| --- | --- | --- |
| 高频重复 | 每周/每个项目都要做 | 每个课程作业都要写设计说明；每场活动都要写方案 |
| 套路稳定 | 步骤大同小异，不是每次都从头想 | 设计说明固定写"背景 → 定位 → 色彩 → 材料 → 创新点"，只换作品；方案 8 项固定，只换游戏 |
| 输出可标准化 | 有明确的合格/不合格标准 | 几项齐不齐、有没有具体数据和依据，老师能逐条核对 |

> 产品/UI 方向补充类比：每次迭代都写的需求文档、固定的 PRD 模板、能逐条核对的验收标准，都符合这三条。

**工作流提取四问**（让学生现场套用）：

1. 我最近反复在做的是哪件事？
2. 每次做它的步骤是不是差不多？
3. 哪一步我最依赖个人经验、或最容易出错？**这一步最该写进 Skill。**
4. 什么样的结果算"合格"？把它写成检查项。

#### ② 方法：四步法固化

**拆任务 → 定流程 → 写指令 → 设输出规范**。以**「会议纪要 Skill」**为例（与 20-33' 演示用的是同一个，学生已看过输出；写方案留作本堂实践）：

| 步骤 | 要做的事 | 会议纪要示例 |
| --- | --- | --- |
| 拆任务 | 把模糊需求拆成明确子任务 | 拆成 6 项：会议主题 → 时间地点 → 参会人 → 议题 → 结论 → 待办 |
| 定流程 | 规定子任务的执行顺序与依赖 | 先议题后结论，再把结论拆成待办 |
| 写指令 | 为每个子任务写清执行要求 | "每条待办写清负责人和截止时间，如'张三 / 本周五前'" |
| 设输出规范 | 规定格式、篇幅、语气、检查项 | 6 项齐全、小标题统一、末尾自检"待办都有人负责吗、有时间吗" |

**上屏写法**：会议纪要是单任务，前三步上屏只放占位符（无需拆分 / 一步完成 / 不需要代码），上表前三步的内容全部写进 STEP 4 的输出规范。讲法：简单任务只写规范就够。

最后补一步：写好 `description`，说清"整理会议记录、写会议纪要时使用"，AI 才能在该用的时候想到它。

**第二个案例：海报多尺寸适配 Skill**（多任务、多步骤、要写脚本）

| 步骤 | 海报多尺寸适配示例 |
| --- | --- |
| 拆任务 | 读取主视觉 → 改 4 个尺寸（朋友圈方图 / 小红书竖图 / 长图 / 易拉宝）→ 检查文字 → 命名导出 |
| 定流程 | 先分出背景层与文字层，再逐个尺寸重排，全部完成后统一检查、统一导出 |
| 写脚本 | `scripts/resize.py` 批量裁切缩放；`scripts/rename.py` 按「组号-物料-尺寸」命名 |
| 设输出规范 | 4 个尺寸齐全；文字不出安全区；主色与原图一致；文件名格式统一 |

讲法：任务一多、步骤一长、要批量处理文件，才需要拆任务、定流程、写脚本。这个案例和后续活动物料制作直接相关。

#### ③ 最佳实践（课上点前两条，其余发口诀卡）

| 实践            | 做法                            | 为什么重要                  |
| ------------- | ----------------------------- | ---------------------- |
| **先手工跑通再固化**  | 先把流程手动做 2-3 遍，确认步骤稳定再写 Skill  | 没验证过的流程写进 Skill，只会每次都错在同一处 |
| **隐性经验显性化**   | 把"怎么判断目标够不够具体""什么算合格"写成文字  | 这一步最难，也最有价值 |
| **描述决定命中率**   | 描述里写全用户的真实说法（含口语），并注明"不适用情形" | 否则 AI 在该用的时候想不起、不该用时乱用 |
| **渐进披露**      | 正文只写骨架，详细规范/参考放资源文件，用到才加载     | 保证 AI 读得完、读得准          |
| **写"常见错误"清单** | 把自己踩过的坑写进去                    | 让 AI 少犯你已经犯过的错         |
| **换说法测试**    | 做完后用不同说法、边缘说法测试，不命中就补描述           | 想不起来用的 Skill 等于没装    |

- **讲法提示**：落点一句话：**"你重复做的事，就是你的第一个 Skill"**。

### 55-60'　拆解内核与轻改造

- **目标**：建立"我也能定制"的信心，为下半场的改造动作做示范。
- **内容要点**：
  - 打开会议纪要 Skill 的 `SKILL.md`，在输出规范里加一句指令（例如"末尾增加一行：下次会议时间"），用同一段会议记录重跑，展示输出随之变化。
  - 指给学生看改的是哪一段（输出规范），对应三要素里的哪一项。
- **讲法提示**：只做一处改动、一次重跑，控制在 5 分钟内。任务发布统一放到 60' 之后。如果市场 Skill 不允许直接编辑，演示"复制一份 → 本地导入 → 修改"的路径（课前确认，见第九节）。

## 五、讨论及实践段详细设计（60-120'）

### 60-70'　任务发布 + 找 Skill

- **形式**：各组把宣讲里的活动想法，写成一份**活动策划方案**，做三版对照：

| 版本 | 做法 | 作用 |
| --- | --- | --- |
| A 裸聊版 | 不用 Skill，直接发需求描述 | 对照基线 |
| B Skill 原版 | 用自己找到的 Skill，发**同一句**需求描述 | 看现成 Skill 带来什么 |
| C Skill 改造版 | 把 8 项规格写进这个 Skill 的输出规范，再发**同一句**需求描述 | 看改输出规范带来什么 |

- **控制变量**：三版用同一句需求描述，例如"帮我把【活动名】写成一份活动策划方案，活动概念和亮点如下：……"。**8 项要求只能写进 Skill，不能写进需求描述**，否则看不出差异来自哪里。
- **交付观**：交付的是"结构完整、目标可量化、能指导后续执行"的方案，不是一段漂亮文案。
- **铁律重申**：**Skill 不指定，各组自己想办法找**：到技能市场搜、看描述判断、装一个试跑；实在找不到用内置文档能力兜底（兜底时 B、C 两版合并为"内置能力 + 自建 8 项规范"一版，在对比记录里注明）。找不到合适 Skill 的组，讲师只提示搜索关键词，不代劳指定。
- 本段最后 5 分钟各组完成搜索与安装，70' 准时开跑。

**活动策划方案 8 项规格**（投影展示，全程可见；与题目规格一致）：

| 项 | 内容 | 合格线 |
| --- | --- | --- |
| 1 活动背景 | 为什么办这场活动、和游戏 IP 的关系 | 有具体由头，不是套话 |
| 2 活动目标 | 要达成什么 | **可量化**（到场人数 / 传播量 / 新增关注，如到场 ≥ 300 人） |
| 3 目标受众 | 面向谁 | 有人群画像，能指导后续报名问卷设计 |
| 4 活动流程 | 活动怎么进行 | 时间轴，写清几点做什么 |
| 5 场地与物料 | 在哪办、要什么物料 | 场地需求 + 物料清单，物料清单与宣讲第 5 页对得上 |
| 6 预算与资源 | 花多少钱 | 有分项的粗略估算 |
| 7 风险与预案 | 可能出什么岔子 | **至少 2 条**，每条有预案 |
| 8 成功标准 | 怎么算办成了 | 可逐条核对，和活动目标对应 |

- **评判口径**（投影展示，全程可见）：

| 维度    | 权重  | 判断标准                    |
| ----- | --- | ----------------------- |
| 结构完整度 | 30% | 8 项齐不齐                |
| 专业度   | 30% | 目标可量化、流程可执行、风险有预案          |
| 规范符合度 | 20% | 格式统一；物料清单与宣讲第 5 页对得上         |
| 可复现性  | 20% | 用改造后的 Skill 再跑一次，8 项结构不变；差异能追溯到 Skill 的具体段落 |

### 70-95'　上手实践（三版输出）

- **三段走**：
  - 70-75'：A 裸聊版，发需求描述，输出留档。
  - 75-82'：B Skill 原版，同一句需求描述，输出留档。
  - 82-95'：C Skill 改造版，打开 Skill，把 8 项规格和合格线写进输出规范，重跑一次；时间允许再跑一次，看结构是否稳定。
- 讲师巡场，**重点纠偏**：只会点按钮、不看输出规范；把 8 项要求写进了需求描述（破坏对照）；不做对比直接交一版；目标写成"让更多人知道"这类无法量化的虚词；物料清单和宣讲对不上。
- 提醒时间节点：95' 进入讨论。

### 95-110'　对比讨论

- 学员对比三版方案，填写**对比记录**（格式见下），围绕三问讨论：
  1. **8 项齐不齐？**（A、B、C 各漏了什么）
  2. **差异由 Skill 的哪部分结构造成？**（B 比 A 多出的来自现成 Skill 的哪段；C 比 B 多出的来自你改的哪一句）
  3. **方案里的物料清单，与宣讲 PPT 第 5 页对不对得上？**（检验前后一致）

**对比记录格式**（与题目规格一致，增加 B 列）：

| 对比项 | A 裸聊版 | B Skill 原版 | C Skill 改造版 |
| --- | --- | --- | --- |
| 结构是否完整（8 项齐不齐） | | | |
| 有没有漏项 | | | |
| 格式是否统一 | | | |
| 是否有 AI 套话 | | | |
| 差异来自 Skill 的哪部分 | — | | |

### 110-117'　成果分享

- 学员自愿分享一条关键发现。
- 讲师归纳落点：**Skill 是可复用的流程；选对 Skill、把要求写进输出规范，方案就能结构稳定、不漏项。**

### 117-120'　产出收口

- **当堂任务**：各组定稿活动策划方案（C 版，8 项），连同对比记录一起留存。
- **要求**：按本节 8 项规格整理并命名（`组号-游戏名-活动策划方案`），当堂收齐；未完成的第 3 场开场 10 分钟补齐。

## 六、产出与衔接

- **本场产出** → 活动策划方案（8 项 + 三版对比记录）
- **下一场衔接**：第 3 场用连接器把本场方案里的**真实信息**（时间、地点、亮点）+ 官方游戏素材接入，通过腾讯问卷连接器创建在线报名问卷。方案是问卷的输入，不是"个人作品素材"。

## 八、设计逻辑说明

- **认知递进**：历史铺垫（为什么）→ 体验先行（看见差异）→ 原理拆解（是什么、写在哪）→ 方法内化（怎么做）→ 轻改造（我也能做）。
- **弱化步骤、强化思维**：全程不逐条讲操作按钮，而是围绕"功能搭配思维"展开。
- **评图式讨论**：沿用设计专业熟悉的"对比—点评—归纳"方式，让学生从三版输出的差异中自己得出结论，而非被动接收功能清单。
- **控制变量**：三版只改一个条件（有无 Skill、有无改造），差异才能追溯到 Skill 的具体结构，对比讨论第 2 问才有答案。
- **任务性质对齐**：本节是"用 Skill 干活"（写方案），不是"造 Skill"；造 Skill 的方法作为知识讲授保留，改输出规范是实践里唯一的"动手改"动作。

## 九、来源说明与课前核对

- **Skill 来源已定**：全部使用 **WorkBuddy 平台提供的 Skill**（市场安装 + 内置能力两类），不预制、不自建。
- **推荐依据**：《设计类学生常用 skill 列表》（WorkBuddy 在线 Page，链接见文末），已按场景收录至 33-45' 工具地图，名称按平台实际展示填写。
- **课前必做**：
  1. 在市场里搜"策划/方案/活动/文档"实测一遍，确认至少 1 个写方案类 Skill 可安装可用，**作为兜底**，但不指定给学生，让学生自己搜；
  2. **在技能市场搜第 8、9 页列出的 Skill 名称**，确认是否已上架；未上架的从 GitHub 下载后本地导入；
  3. **核对 WorkBuddy 中 Skill 的文件结构**：是否为 `SKILL.md`（含 `name` / `description`）+ `scripts/` / `references/` / `assets/` 的 Agent Skills 规范结构；如有差异，按平台实际结构改写 20-33' 的三要素位置表；
  4. **核对市场 Skill 能否直接编辑**：不能的话，确认"复制 → 本地导入 → 修改"的路径可走通，实践 C 版依赖这一步；
  5. 确认会议纪要 Skill 可展示内部结构、可现场改指令，供 20-33' 与 55-60' 演示；
  6. 内置能力（ImageGen / 图片处理 / PPT / 思维导图 / Word）开箱即用，作为找不到 Skill 时的兜底。
- **风险提示**：市场 Skill 的安装状态、可用模型（如 AI Hive 下的 GPT Image 2 / Nano Banana）可能变动，开课前实测一遍；若演示 Skill 临时不可用，切到内置能力兜底，并用课前截图展示两版差异。课堂重点是**选型逻辑与结构判断**：本节考的是"能不能找到并用好一个 Skill 写出结构稳定的方案"，不是记住某个 Skill 名。
