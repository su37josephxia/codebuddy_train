## 四、授课段详细设计（0-60'）

### 0-8'　复盘与答疑

- **目标**：承接第 1 场，把注意力收拢到本场主线。
- **要点**：点评上一场"功能地图"作业；收集疑问；抛出主线问题——**"设计到底靠灵感，还是靠流程？"**
- **讲法提示**：不急着回答这个问题，留到 20-33' 用输出差异来回答。

### 8-20'　Skill 发展史（定义 + 必要性）

- **目标**：先讲清"为什么会有 Skill"，再讲"它是什么"，让学生理解其必然性。
- **内容要点**：
  - 三代演进（讲师话术参考）：
    - **第一代·对话式 AI**：一问一答，输出随机，每次都要重新描述需求，好结果无法沉淀。
    - **第二代·提示词技巧**：靠写长提示词换取好输出，但提示词散落在个人笔记里，难复用、难协作。
    - **第三代·Skill 技能**：把"流程 + 脚本 + 规范"打包固化，一键调用，输出稳定、可复用、可迭代。
  - **定义**：Skill = 把一套标准化的专业工作流程封装成可复用的 AI 能力包。
  - **必要性**：设计的价值不只在于灵感，更在于可复现的专业工序。Skill 让"好方法"留得下来、传得出去。
- **讲法提示**：用学生熟悉的场景类比——"就像设计系的字体规范/VI 手册：把审美判断固化成标准，新人也能稳定产出"。

### 20-33'　先体验、后拆原理

- **目标**：用输出差异钩住注意力，再顺势拆解原理。
- **内容要点**：
  1. 现场用同一个任务跑两遍：一版"裸聊"（直接对话），一版调用 **WorkBuddy 平台自带的 Skill**。
  2. 并排展示两版输出，让学生先说差异。
  3. 顺势拆出公式：**Skill = 标准工作流程 + 任务脚本 + 输出规范**。
  4. 破除误解："Skill 不是按钮，按钮背后是一整套被写好的专业判断。"
- **讲法提示**：差异要"看得见"——选结构感强的任务（设计说明），裸聊版通常散、漏项，Skill 版结构完整，对比一目了然。

### 33-45'　设计适配 Skill 选型

- **目标**：从"有哪些 Skill"转向"什么场景选哪个"。
- **内容要点**：聚焦 2-3 个设计相关 Skill 讲判断标准，不做功能罗列。以下推荐来自《设计类学生常用 skill 列表》（WorkBuddy 在线 Page），名称按平台实际展示填写。

**① 本场任务相关的选型判断（先讲逻辑，再给名字）**

| 场景 | 选用方向 | 判断标准 |
|---|---|---|
| 写作品说明/设计阐述 | 海报/平面生成类 Skill（多数附带设计说明输出） | 需要结构化、固定版式、专业术语 |
| 选题发散/灵感枯竭 | 生图类 Skill + 图片处理内置能力 | 需要突破惯性、多方向铺开 |
| 毕设/求职材料整理 | PPT / 思维导图 / Word 内置能力 | 需要框架先行、逻辑统一 |

**② 设计类学生高频 Skill 推荐（按场景，真实名称）**

| 场景 | Skill 名称 | 干什么 | 来源 |
|---|---|---|---|
| 海报/平面 | AI 海报生成与编辑｜中文文字与商业设计 | 文字或参考图生成海报、电商主图、KV，支持中文文字与商业设计 | 市场安装 |

### 45-55'　Skill 制作方法论

- **目标**：让学生理解 Skill 是可被设计、可被优化的产物，并掌握一条自己就能上手的路子。
- **核心路径**：**从已有工作流提取 → 按四步法固化 → 用最佳实践打磨**。强调"不用凭空想 Skill，你重复做的事就是素材"。

#### ① 入口：工作流提取法（重点讲）

把自己反复做的工作剥离成 Skill，是最实用、最容易成功的路径。判断一件事值不值得提取，看三条：

| 判断标准 | 说明 | 设计场景举例 |
|---|---|---|
| 高频重复 | 每周/每个项目都要做 | 每份作业都要写的设计说明 |
| 套路稳定 | 步骤大同小异，不是每次都从头想 | 作品集排版、竞品分析、调研框架 |
| 输出可标准化 | 有明确的好/坏、合格/不合格标准 | 色彩释义、设计报告、答辩文案 |

**工作流提取四问**（让学生现场套用）：

1. 我最近反复在做的是哪件事？
2. 每次做它的步骤是不是差不多？
3. 哪一步我最依赖个人经验、或最容易出错？——**这就是最该写进 Skill 的部分**
4. 什么样的结果算"合格"？——把它写成检查项

#### ② 方法：四步法固化

**拆任务 → 定流程 → 写脚本 → 设输出规范**。以"设计说明撰写 Skill"为例：

| 步骤 | 要做的事 | 设计场景示例 |
|---|---|---|
| 拆任务 | 把模糊需求拆成明确子任务 | 拆成：项目背景 → 设计定位 → 色彩释义 → 材料工艺 → 创新点 |
| 定流程 | 规定子任务的执行顺序与依赖 | 先定位后释义，先事实后评价 |
| 写脚本 | 为每个子任务写清执行指令 | "色彩释义需说明主色、辅色及情绪指向" |
| 设输出规范 | 规定格式、篇幅、语气、检查项 | 分小标题、每项 80-120 字、学术客观语气、末尾自检清单 |

#### ③ 最佳实践（讲 2-3 条，其余发口诀卡）

| 实践 | 做法 | 为什么重要 |
|---|---|---|
| **先手工跑通再固化** | 先把流程手动做 2-3 遍，确认步骤稳定再写 Skill | 没验证过的流程写进 Skill 只会稳定地错 |
| **隐性经验显性化** | 把"怎么判断配色好不好""什么算合格"写成文字 | 这一步最难也最值钱，Skill 的价值全在这 |
| **描述决定命中率** | 触发描述写全用户的真实说法（含口语），并注明"不适用情形" | 否则 AI 在该用的时候想不起、不该用时乱用 |
| **渐进披露** | 正文只写骨架，详细规范/参考放资源文件，用到才加载 | 保证 AI 读得完、读得准 |
| **写"常见错误"清单** | 把自己踩过的坑写进去 | 让 AI 少犯你已经犯过的错 |
| **故意演砸验证** | 做完后用边缘说法测试，不命中就补触发词 | 命中率是 Skill 能不能用的生死线 |

- **讲法提示**：这是本场"思维含金量"最高的一段。10 分钟有限，**课上重点讲①工作流提取法的四条判断 + 四问，以及③的前两条（先跑通、经验显性化）**，其余发口诀卡课后看。落点一句话——**"你重复做的事，就是你的第一个 Skill"**。

### 55-60'　拆解内核与轻改造

- **目标**：建立"我也能定制"的信心，并发布下半场任务。
- **内容要点**：
  - 打开一个 Skill 的内部结构，现场改一句脚本，展示输出如何随之变化。
  - 发布下半场任务与评判口径；明确时间节点。

## 五、讨论及实践段详细设计（60-120'）

### 60-70'　任务发布

- **任务**：学员独立完成——"为指定作品写一份设计说明"。
- **双轨产出**：同一任务做两版——① 裸聊版；② Skill 版。
- **评判口径**（投影展示，全程可见）：

| 维度 | 权重 | 判断标准 |
|---|---|---|
| 结构完整度 | 30% | 是否覆盖背景/定位/色彩/材料/创新点等必要项 |
| 专业度 | 30% | 术语准确、释义有依据、不空泛 |
| 规范符合度 | 20% | 格式、篇幅、语气是否符合要求 |
| 可复现性 | 20% | 方法能否迁移到下一份作品 |

### 70-95'　上手实践

- 学员独立跑完双轨输出；讲师巡场。
- **重点纠偏**：只会点按钮、不看输出规范；把 Skill 当搜索框用；不做对比直接交一版。
- 提醒时间节点：95' 进入讨论。

### 95-110'　对比讨论

- 学员对比两版输出，围绕三问讨论：
  1. **差异在哪？**（结构、完整度、专业度、稳定性）
  2. **差异由 Skill 的哪部分结构造成？**（对应三要素与四步法）
  3. **我的专业还适合哪些 Skill？**（迁移到视觉/产品/环艺/数媒的具体场景）

### 110-117'　成果分享

- 学员自愿分享一条关键发现。
- 讲师归纳落点：**Skill = 可复用工序；选对场景 + 用好规范 = 稳定产出。**

### 117-120'　小结与作业

- **作业**：用 1 个 Skill 完成一份标准化设计输出。
- **要求**：明确产出形态（设计说明或作品阐述），供第 3 场"上传个人作品"使用。

## 六、作业与衔接

- **本场作业** → 学员的标准化设计输出
- **下一场衔接**：第 3 场开场展示本场 Skill 输出质量对比，并以此作为"上传个人作品"的素材起点。

## 七、讲师准备清单

| 类别 | 准备项 | 状态 |
|---|---|---|
| Skill 素材 | 按 33-45' 推荐表挑 2-3 个设计 Skill 并**提前安装**（如 AI 海报生成与编辑、海报生图器、UI 设计）；内置能力（ImageGen/图片处理/PPT）无需安装 | 待课前安装并跑通 |
| 演示素材 | 1 个可展示内部结构、可现场改脚本的 Skill（建议用内置能力或一个已安装 Skill） | 待课前确认 |
| 任务素材 | 指定作品图（海报或产品图）1 张 | 待准备 |
| 教学物料 | 评判口径表（投影/打印） | 待准备 |
| 对比样例 | 裸聊版与 Skill 版设计说明各 1 份（备用的"翻车样本"） | 待准备 |

## 八、设计逻辑说明

- **认知递进**：历史铺垫（为什么）→ 体验先行（看见差异）→ 原理拆解（是什么）→ 方法内化（怎么做）→ 轻改造（我也能做）。
- **弱化步骤、强化思维**：全程不逐条讲操作按钮，而是围绕"功能搭配思维"展开。
- **评图式讨论**：沿用设计专业熟悉的"对比—点评—归纳"方式，让学生从两版输出的差异中自己得出结论，而非被动接收功能清单。

## 九、来源说明与课前核对

- **Skill 来源已定**：全部使用 **WorkBuddy 平台提供的 Skill**（市场安装 + 内置能力两类），不预制、不自建。
- **推荐依据**：《设计类学生常用 skill 列表》（WorkBuddy 在线 Page，链接见文末），已按场景收录至 33-45' 选型表，名称按平台实际展示填写。
- **课前必做**：
  1. 从推荐表挑 2-3 个 Skill **提前安装并跑通**（市场安装类），建议覆盖海报/平面、UI/原型各 1 个；
  2. 确认其中 1 个可展示内部结构、可现场改脚本，供 55-60' 演示；
  3. 内置能力（ImageGen / 图片处理 / PPT / 思维导图 / Word）开箱即用，无需安装，可作为兜底。
- **风险提示**：市场 Skill 的安装状态、可用模型（如 AI Hive 下的 GPT Image 2 / Nano Banana）可能变动，开课前实测一遍；若演示 Skill 临时不可用，切到内置能力兜底，课堂重点仍是"选型逻辑"——本场考的是判断力，不是记住某个 Skill。
