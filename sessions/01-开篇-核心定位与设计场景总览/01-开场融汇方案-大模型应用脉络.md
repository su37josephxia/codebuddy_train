## 一、参考讲法拆出来是什么

那条分享的提问是「我一直搞不懂豆包、Dify 与龙虾的区别」，回答的骨架是六步：

1. **一句话极简定位**：豆包＝大模型（大脑，思考、问答、生成）；Dify＝AI 应用搭建平台（组装模型、知识库、工作流，对外发布机器人）；龙虾 OpenClaw／LobsterAI＝桌面 Agent 执行框架（手脚，操作本机软件、文件、浏览器去干活）。
2. **先破一个误解**：Dify 和龙虾本身都没有大模型能力，都必须接豆包、DeepSeek、Claude 这类模型才跑得起来。
3. **逐个拆身份与边界**：豆包只回文字、不碰本机文件；Dify 交付一个可发布的应用／API；龙虾交付本机上跑完的一整套任务。
4. **一张对照表**：核心身份 / 能否操控本地文件 / 交付形式 / 最佳场景。
5. **形象比喻**：军师（出主意）→ 装修工作台（把军师和资料拼成服务）→ 干活的助理（上手把活做完）。
6. **组合关系收口**：不是三选一，常见的是叠着用（豆包＋Dify 做问答机器人，豆包＋龙虾做本机自动化）。

**这套讲法最值钱的两点，正是第 1 场缺的：**

- **用学生见过的具体产品当锚点讲抽象脉络**，不从「AI 概念期」这种编年史讲起；
- **讲分工与叠加，不讲谁替代谁** —— 这条正好是整门课「连接器＋Skill＋专家」搭配思维的预演。

## 二、融在哪、怎么融

### 2.1 现有 §三 的问题

现有 `10-35'`「什么是 AI 工作台」是：六阶段演进（AI 概念期 → GPT → 大语言模型 → 智能体 → 工作台类出现 → 品类分化）→ 品类归纳（五部件、边界三条）→ 三层封装（框架层 / 平台编排层 / 自主工作台层）→ 落点。

- 六阶段是技术编年史，前 10 分钟对设计专业学生没有可感知的东西；
- 三层封装用 LangChain / Dify / Coze 做代表，学生大多没见过，听完只剩名词；
- **但它的结论是对的、且必须保留**：五部件、边界三条、「底层能力大致相同，区别在要你先做多少和最后交给你什么」，以及 P12 把五部件接到三大组件的落点。

### 2.2 融合策略：换开头，不换结论

| 部位 | 处理 |
|---|---|
| 六阶段编年史 | **替换**为三段应用脉络，用具体产品当锚点 |
| 品类归纳（定义 / 五部件 / 边界三条） | **保留**，作为「引出智能工作台」的落点 |
| 三层封装对比表 | **保留但加一层铺垫**：先上产品对照表（讲得懂），再抽象成封装层级（讲得准） |
| P12 落点（五部件 → 连接器 / Skill / 专家） | **原样保留**，它负责把 35-45' 三大组件演示接起来 |
| 时间 | 仍占 `10-35'`（25 分钟），与总纲第 1 场原表 `10-40'` 核心定位不冲突，只是把这段讲法换掉 |

一句话：**从「按年份讲发生了什么」改成「按学生用过的工具讲每一步还差什么」**，结论不变，路径更好走。

## 三、融合后的段落大纲（`10-35'`，25 分钟）

主线：**能聊 → 能搭 → 能干（自主交付）→ 引出智能工作台**。
贯穿例子统一用设计学生的真实任务，三段不换题：**「给认领的游戏做一张宣讲海报」**。

| 步 | 时间 | 讲什么 | 怎么讲 | 落点 |
|---|---|---|---|---|
| 1 · 起困惑 | 3' | 先收真实回答：「你平时用哪些 AI 做设计？」 | 不评判，只把回答写到黑板上，自然分成三堆：豆包 / DeepSeek 类、Dify / 扣子类、龙虾 / 智能工作台类。学生会自己发现「大家用的不是一类东西」 | 从学生的产品名出发，不从概念出发 |
| 2 · 一句话定位 | 4' | 三个词：**大脑 / 编排台 / 手脚** | 借用参考讲法的极简定位，但按课程口径改名（见 §四.1）。每个词只配一句：谁在动手、交给你什么 | 三个词记住，先不展开 |
| 3 · 三段脉络 | 8' | 能聊 → 能搭 → 能干，每段只讲两件事：**解决了什么、还差什么** | 用同一张海报串到底：<br>**能聊**：给 3 个亮点、一段海报文案，复制粘贴、找图、排版、导出还是你自己做<br>**能搭**：把品牌规范＋亮点生成＋固定版式搭成一个应用，改一次需求要回去改节点、重新发布<br>**能干**：说清需求、贴一张参考图，它自己找素材、按流程做、把 PNG 交出来，不满意在同一处接着改 | 脉络成形，学生会自己说出「那我需要第三种」 |
| 4 · 破误解 + 对照表 | 6' | 三者不是替代关系：后两类自己没有大模型，都要接豆包这类大脑 | 上对照表（见 §3.1），收在一句关键结论：**底层是同一个大脑，差别在「要你先做多少」和「最后交给你什么」** —— 这句直接接现有 §3.3 的原结论，不新增观点 | 从具体产品过渡到抽象分层，接缝在这里 |
| 5 · 引出智能工作台 | 4' | 归纳成一类：定义 + 五部件 + 边界三条 + 落点 | 五部件：模型 / 资料 / 工具 / 流程 / 标准。边界三条按现有 §3.2 原样讲。落到 WorkBuddy 在最上层：说清需求，它自己规划执行，交付能直接用的文件；五部件落到这台机器上就是**连接器（资料＋工具）· Skill（流程）· 专家（标准）**，模型由平台预置 | 接上 `35-45'` 三大组件演示；后面 50 分钟上手就是练「说清需求、给材料、验收」 |

合计 3＋4＋8＋6＋4＝25 分钟。

### 3.1 第 4 步的对照表（课程口径版）

| 形态 | 代表（只作锚点） | 谁在动手 | 交付什么 | 你要先做多少 |
|---|---|---|---|---|
| 对话型 | 豆包 / DeepSeek | 只出文字 | 一段回答 | 说一句话 |
| 编排型 | Dify / 扣子 | 按你预先画的流程跑 | 一个可发布的应用 / API | 先搭流程、配资料、发布 |
| 工作台型 | WorkBuddy | 自己规划并执行 | 能直接用的文件（文档 / 表格 / PPT / 图片 / 网页） | 说清需求、给材料、验收结果 |

表格下面一句：**三类都靠同一个大模型当大脑，区别不在模型，在模型之上被组织起来的东西有多少。**

> 现有 §3.3 的「框架层 / 平台编排层 / 自主工作台层」抽象表不删，放在这张表之后作为「再抽象一层」，两页连着讲。基础弱的学生记住产品对照表就够，想深一层的看封装层级。

### 3.2 开场三问的处理

现有 P02「开始之前，先问三个问题」不动，但**讲师话术里把第 1 步的「你平时用哪些 AI」并进去**：三问收完、写在黑板上，顺势归类。这样 P02 不用改页，只改讲义里的话术要点。

## 四、关键口径修正（写进讲义，避免和现有材料打架）

1. **「工作台」一词会被占用**。参考讲法把 Dify 叫「工作台」、龙虾叫「执行框架」，而本课程「AI 工作台 / 智能工作台」专指 WorkBuddy 这一类。课上统一口径：**中间那层只叫「应用搭建平台」或「编排台」，不叫工作台**；「智能工作台」只留给「说清需求 → 自主规划 → 交付成品」这一层。否则与 P09 定义、P11 三层表、P12 落点、总纲「核心定位」互相矛盾。
2. **「龙虾 / OpenClaw」只作 1 分钟热点锚点，不展开**。学生大概率听过「养龙虾」，用它把第三类形态叫醒就够了；不谈部署、成本、安全争议 —— 那是选型话题，且第 1 场是授课节，时间紧。落点立刻回到 WorkBuddy。
3. **不做竞品比较、不给选型建议**。三个产品只当脉络锚点，不评优劣、不谈价格。学生若问「那我到底装哪个」，统一回答：「今天只装一台，就是待会儿要上手的这台」。
4. **不新增观点上屏**。三段脉络、对照表、五部件这些都要先补进 `01-讲义.md`，再从讲义提炼逐页大纲；确认后才改 HTML（AGENTS.md §5.2 / §5.7）。
5. **比喻可以用，但按 §5.6 去 AI 味**：用「军师 / 编排台 / 干活的助理」这种朴素说法，不写「不是 A 而是 B」对偶、不写破折号追加解释、不写「从 X 到 Y 是必然的演进」。

## 五、与全课主线的接缝（为什么这样融不会跑偏）

- 第 4 步「底层同一个大脑，差别在模型之上组织了多少东西」＝ 现有 §3.3 结论 ＝ 全课「不教按钮、教功能搭配思维」的定调；
- 第 5 步五部件 → 连接器 / Skill / 专家 ＝ P12 原落点 ＝ 第 2–4 场逐个拆解的预告；
- 第 3 步「说清需求、贴参考图、在同一处接着改」＝ 后面 `45-95'` 上手段的四要素 + 贴图 + 引用批注，学生会在动手时认出刚才听过的东西；
- 「三者可以叠着用」＝ 第 4 场末万能公式（连接器＋Skill＋专家）的第一次埋线，但本场**不点破**，按现有口径只认三个组件的样子。
