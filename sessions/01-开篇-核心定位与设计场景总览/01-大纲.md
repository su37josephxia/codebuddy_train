## 三、`10-35'` 大模型应用脉络 → 智能工作台（25 分钟）

> **本段按 2026-11-26 融汇方案改写**：用学生见过的具体产品当锚点讲清应用脉络，再引出智能工作台。六阶段技术编年史替换为三段脉络，品类归纳（定义 / 五部件 / 边界三条）、三层封装与 P12 落点全部保留。讲法与口径详见 [01-开场融汇方案-大模型应用脉络.md](./01-开场融汇方案-大模型应用脉络.md)。

**贯穿例子**：「给认领的游戏做一张宣讲海报」，三段不换题。学生是设计专业，例子必须落在设计动作上。

### 3.1 讲法顺序：五步

| 步 | 时间 | 讲什么 | 现场动作 | 落点 |
|---|---|---|---|---|
| 1 起困惑 | 3' | 「你平时用哪些 AI 做设计？」 | 收 3–5 个真实回答，不评判，黑板自然分三堆：对话型 / 编排型 / 工作台型 | 从产品名出发，不从概念出发 |
| 2 一句话定位 | 4' | 三个词：大脑 / 编排台 / 手脚 | 每词只配一句「谁在动手、交给你什么」，不展开 | 先记住三个词 |
| 3 三段脉络 | 8' | 能聊 → 能搭 → 能干 | 每段只讲「解决了什么、还差什么」，用同一张海报串到底（见 3.2） | 学生自己说出「我需要第三种」 |
| 4 破误解 + 对照表 | 6' | 三者不是替代关系；后两类自己没有模型，都要接豆包这类大脑 | 上对照表（见 3.3），收在一句结论 | 从具体产品过渡到抽象分层 |
| 5 引出智能工作台 | 4' | 定义 + 五部件 + 边界三条 + 落点 | 收在 P12 原落点 | 接上 `35-45'` 三大组件演示 |

合计 3＋4＋8＋6＋4＝25 分钟。开场三问（P02）不动，第 1 步并进讲师话术里。

### 3.2 三段脉络的贯穿例子

| 段 | 代表（只作锚点） | 解决了什么 | 还差什么 |
|---|---|---|---|
| 能聊 | 豆包 / DeepSeek | 给 3 个亮点、一段海报文案 | 复制粘贴、找图、排版、导出还是你自己做 |
| 能搭 | Dify / 扣子 | 把品牌规范、亮点生成、固定版式搭成一个应用，流程可复用 | 要先画流程、配资料、发布；改一次需求要回去改节点 |
| 能干 | 智能工作台（WorkBuddy 所在层） | 说清需求、贴参考图，自己找素材、按流程做、把文件交出来 | 落点：不满意在同一任务里接着改 |

> 第三类可点名「龙虾 / OpenClaw」当 1 分钟热点锚点，只用来叫醒这一形态，**不展开部署、成本、安全争议**（见 3.6 口径修正）。

### 3.3 产品对照表（课程口径版）

| 形态 | 代表（只作锚点） | 谁在动手 | 交付什么 | 你要先做多少 |
|---|---|---|---|---|
| 对话型 | 豆包 / DeepSeek | 只出文字 | 一段回答 | 说一句话 |
| 编排型 | Dify / 扣子 | 按你预先画的流程跑 | 一个可发布的应用 / API | 先搭流程、配资料、发布 |
| 工作台型 | WorkBuddy | 自己规划并执行 | 能直接用的文件（文档 / 表格 / PPT / 图片 / 网页） | 说清需求、给材料、验收结果 |

**表格下面一句（关键结论，与 3.5 原结论一致，不新增观点）**：三类都靠同一个大模型当大脑，区别不在模型，在模型之上被组织起来的东西有多少 —— 也就是「要你先做多少」和「最后交给你什么」。

### 3.4 归纳：把这一类划成一个品类（保留）

- **工作定义**：在模型之上，把能力、资料、工具、流程和专业标准组织起来，让 AI 完成多步任务并交付可验收结果的工具。
- **共性五部件**：模型（能力来源）· 资料（判断依据）· 工具（外部动作）· 流程（步骤顺序）· 标准（专业眼光）。
- **共同目标**：把一次性回答，变成可交付、可验收的工作。
- **边界三条**：不是模型本身；不是单个聊天机器人；不绑定单一业务。

### 3.5 对比：品类内部的三个封装层级（保留，作为「再抽象一层」）

| 层 | 谁装配 | 交付什么 | 代表（只作定位） |
|---|---|---|---|
| 框架层 | 开发者写代码 | 能力组件 | LangChain / 各类 SDK |
| 平台编排层 | 人画流程、配节点 | 可部署的应用 / API | Dify / Coze |
| 自主工作台层 | 说清需求，AI 自主规划 | 文档 / 表格 / PPT 等成品 | WorkBuddy |

**核心差异一句话**：底层能力大致相同，区别在「要你先做多少」和「最后交给你什么」。
两张表连着讲：基础弱的学生记住 3.3 的产品对照表就够，想深一层的看这一张抽象表。

### 3.6 口径修正（写进讲义，避免与现有材料打架）

1. **「工作台」一词会被占用**：参考讲法把 Dify 叫「工作台」，而本课程「AI 工作台 / 智能工作台」专指 WorkBuddy 这一类。课上中间层只叫「应用搭建平台」或「编排台」，不叫工作台；「智能工作台」只留给「说清需求 → 自主规划 → 交付成品」这一层。否则与 P10 定义、P11 三层表、P12 落点、总纲「核心定位」互相矛盾。
2. **「龙虾 / OpenClaw」只作 1 分钟热点锚点，不展开**：不谈部署、成本、安全争议，落点立刻回到 WorkBuddy。
3. **不做竞品比较、不给选型建议**：三个产品只当脉络锚点。学生问「那我到底装哪个」，统一答「今天只装一台，就是待会儿要上手的这台」。
4. **不新增观点上屏**：三段脉络、对照表、五部件先补进讲义，再从讲义提炼逐页大纲，确认后才改 HTML。
5. **比喻按 AGENTS.md §5.6 去 AI 味**：用「军师 / 编排台 / 干活的助理」这类朴素说法，不写破折号追加解释、不写「不是 A 而是 B」对偶、不写「从 X 到 Y 是必然的演进」。

### 3.7 落点（1 分钟，保留）

本场要装的 WorkBuddy 属于最上一层的自主工作台：说清需求，它自己规划执行，交付能直接用的文件。五部件落在这个工具上就是后面会用到的东西：连接器（资料 + 工具）· Skill（流程）· 专家（标准），模型由平台预置。本场只认位置，不展开。

## 四、`35-45'` 三大组件简单演示（10 分钟）

| 组件 | 演示什么 | 一句话定位 | 本场不讲 |
|---|---|---|---|
| 连接器 | 挂一个本地文件夹 / 资料，让工具读到真实材料 | 把资料和外部工具接进来 | 接入方式、权限细节、多格式处理 |
| Skill | 跑一个现成技能，看输出结构变化 | 把专业流程固化成可复用的一步 | 选型、制作方法、内核结构 |
| 专家 / 专家团 | 切换一个专家，看同一问题的口吻与标准变化 | 给 AI 一个固定专业身份 | 配置六要素、专家团拆解 |

**统一口径**：本场只要认得「长什么样、点了会发生什么」；原理与制作在第 2–4 场，本场不提问、不深入。

### 5.1 安装与登录（10 分钟）

| 讲什么 | 学员要会 | 常见坑 |
|---|---|---|
| **环境要求**：macOS 12 (Monterey) 及以上；Windows 10 及以上（x64，不支持 7/8/8.1）；Linux 走系统应用商店 | 课前自查系统版本（苹果菜单 → 关于本机） | 系统版本不达标，装了也起不来 |
| **下载与选版本**：官网 workbuddy.cn → 立即下载。Mac 选 M 系列 → ARM64，Intel → X64；未识别时默认 X64（可经 Rosetta 运行，兼容性更广） | 选对芯片版本 | Intel 机器装了 ARM64 包，跑不起来 |
| **安装**：Mac 双击 `.dmg` → 把 WorkBuddy 拖进 Applications；Windows 双击安装包 → 同意协议 → 选路径 → 完成 | 独立装好 | **Mac 直接从磁盘映像里运行**（没拖进应用程序），之后无法自动更新 |
| **登录**：点登录 → 浏览器打开 workbuddy.cn → 勾选《用户服务协议》《隐私政策》→ 微信扫码（也支持手机号、邮箱、SSO） | 登录成功、看到主界面 | 协议没勾、扫码超时、浏览器没弹出来 |
| **语言与更新**：左下角头像 → 设置 → 通用 → 语言；头像 → 检查更新 | 会自己改语言、查版本 | 版本落后，界面与课件截图对不上 |

> 官网有专门的安装指南页，课前把链接和截图发给学员；课上只演示卡点，不逐条念步骤。

### 5.2 认识工作界面（5 分钟）

官网口径的四个区域：

| 区域 | 位置 | 干什么 |
|---|---|---|
| 工具栏 | 顶部 | 关于 WorkBuddy、编辑、窗口等常用操作入口 |
| 侧边栏 | 左侧 | 任务列表（按空间 / 文件夹分组），支持搜索与管理；底部是头像，进设置 |
| 对话区 | 中间 | 任务标题栏 + 消息列表 + 输入框，核心交互区 |
| 结果区 | 右侧 | 产物、网页、工作空间文件、变更，按页签切换 |

**一句话记法**：需求打在对话区，成品在结果区，历史和设置都在侧边栏。
**学员要会**：30 秒内指出四个区，说出「新建任务、历史任务、产物、设置」各在哪。
**常见坑**：把结果区当对话区用；找不到产物；不知道设置藏在侧边栏底部头像里。

### 5.3 创建任务：把需求说清（12 分钟）

官方给的创建路径是四件事：

1. **描述任务**：一句话说清需求即可，不需要预先拆步骤；也可以点输入框的**语音输入**口述，语音实时转文字。
2. **选工作模式 / 用提示词模板**：新建任务页按场景（日常办公 / 代码开发 / 设计创意）提供提示词模板；鼠标悬停会用灰字预览模板内容，点一下才真正填入。
3. **选择工作空间**：点输入框左下角「选择工作空间」，指定这次任务读写哪个目录；不选则在默认目录生成结果。
4. **添加上下文**（四种方式）：

| 方式 | 操作 | 设计场景怎么用 |
|---|---|---|
| @ 引用 | 输入 `@` 引用文件、文档、规则 | 引用活动 Brief、品牌规范、作品集要求 |
| 粘贴截图 | `Cmd / Ctrl + V` | **贴参考图、竞品截图、手绘草图** —— 设计场景最高频 |
| 上传文件 | 点上传按钮，或把文件拖进输入框 | 素材、字体说明、往期物料 |
| 补充说明 | 在描述里写清目标、范围、约束、预期输出 | — |

**官方建议的四个必填要素**（每次发任务都说全）：

| 要素 | 要写什么 |
|---|---|
| 目标是什么 | 要生成什么内容，或要处理什么文件 |
| 输入是什么 | 需要分析的数据、参考的文档 |
| 输出格式 | Word / Excel / PPT / 图片，还是网页 |
| 约束条件 | 风格要求、字数、尺寸、截止时间 |

**学员要会**：独立发出一个四要素齐全、至少带一个上下文的任务。
**常见坑**：需求写成一长段散文；不给上下文让它猜；不指定输出格式；**工作空间选错，产物散落在默认目录**。

### 5.4 任务对话：不满意就接着改（8 分钟）

| 讲什么 | 学员要会 |
|---|---|
| **三类追问**：补充要求（再加一页）、调整结果（标题字大一点）、继续深入（导出 PDF / 换配色） | 结果不理想时不重开任务，直接在同一任务里改 |
| **执行中追加消息**：模型还在跑时可以继续发，消息进队列，可编辑、删除、拖动排序 | 知道不用干等它跑完 |
| **回退 / 编辑 / 刷新**：回退只退回某条消息之前（不重新生成）；编辑会从该条重新开始；刷新只重做最后一条。三者都可能影响已生成的产物，会弹确认框 | 分得清「改一下」和「重来一遍」 |
| **上传与粘贴**：支持 PDF / Word / TXT / Markdown / Excel / CSV / PPT / JPG / PNG / GIF / BMP / ZIP / RAR 及常见代码文件；`Cmd / Ctrl + V` 贴图 | 知道图和文件能直接丢进去 |
| **引用模型输出**：选中回复里某段文字 → 「添加到对话」，可加批注；表格、组件右上角也有「添加到对话」 | **只改某一段、某个表，不整个重做** |
| **中断与继续**：执行中可随时停，停完补充说明接着说 | 发现方向错了立刻停 |
| **隐私边界**：文件默认本地处理不上传；只能访问主动勾选授权的文件夹；高危操作二次确认 | 敢把客户素材放进去 |

**学员要会**：对同一份结果做一次「引用 + 批注」的精准修改。
**常见坑**：结果不对就新建任务，上下文全丢；直接复制对话里的文字，不去拿产物文件。

### 5.5 结果查看：产物在哪、怎么拿走（8 分钟）

结果区按页签组织：

| 页签 | 看什么 |
|---|---|
| 产物 | 任务生成的文件与交付物：文档、表格、PPT、报告 |
| 网页 | 生成的网页、页面原型、Web 应用 |
| 工作空间文件 | 当前工作空间里的文件，按文件树浏览 |
| 变更 | 本次任务改了哪些文件、改了什么 |

> 官方简介页把这块描述为「概览 + 产物」，结果查看页列的是四个页签，以现场界面为准。

**产物卡片「⋯」菜单**：打开文件夹 / 在默认应用打开 / 添加到对话框 / 复制路径 / **另存为** / 上传到云端（资料库 · 腾讯文档 · ima 知识库 · 乐享知识库，需先授权）。
**分享产物**：生成分享链接、直接发到微信 / 企业微信（需本机已登录对应客户端）。

**验收三看**：文件在不在 → 打开看内容对不对 → 格式能不能直接用。
**学员要会**：找到产物、在默认应用打开、另存到本组文件夹。
**常见坑**：只看对话里的摘要就交差；产物留在默认目录找不到；改完不知道去哪拿最新版。

### 5.6 任务管理：找回、接着做、归档（5 分钟）

| 讲什么 | 学员要会 |
|---|---|
| **列表两块**：任务（最近访问 / 更新）、空间（按工作空间分组的任务） | 两处都能找到自己的任务 |
| **搜索与筛选**：`⌘K` / `Ctrl+K` 全局搜索（任务、空间、产物、资料库都能搜）；筛选按状态、按日期 | 找得回三天前的任务 |
| **状态**：规划中 / 进行中 / 待处理 / 已完成 / 失败 / 已归档；侧边栏另标「已完成未读」「待确认」 | 看状态就知道要不要处理 |
| **继续处理**：点任务卡片进入，基于原有上下文继续，不用重开 | 一个活动一个任务，越用越省事 |
| **常用操作**：置顶、重命名、分享、独立窗口打开、打开文件夹、归档、删除 | 任务名改成「第1场-宣讲初稿」这种能认出来的 |

**建议做法**：一组一个空间，一场课一个任务，产物落在同一文件夹 —— 到第 7 场做成果包时直接打包。

### 5.7 三个必须掌握的基础动作（2 分钟，贯穿全场）

1. **说清需求**：目标 / 输入 / 输出格式 / 约束（官方四要素）
2. **给上下文**：`@` 引用、贴图、拖文件，别让它猜
3. **验收结果**：打开产物看，不合格就用「引用 + 批注」接着改

> 这三个动作对应后面三大组件的用法，本场只练动作，不点破对应关系。开场脉络里「说清需求、贴参考图、在同一处接着改」正好是这三个动作，实操时回头点一句即可。

## 六、`95-120'` 当堂实操与产出收口

### 6.1 实操（95-115'，20 分钟）

用刚学的基础功能，每组生成一版宣讲 PPT / 海报初稿：组名与口号、认领游戏、活动概念、3 个亮点、后续物料清单。

### 6.2 产出①规格

**A. 组队宣讲 PPT（5 页，推荐）**

| 页 | 内容 |
|---|---|
| 1 封面 | 组名 + 口号 + 认领的游戏 IP + 活动名称 |
| 2 团队 | 成员与角色分工（组长/策划/视觉/文案/统筹，可兼任） |
| 3 活动概念 | 要办什么活动、为什么选这款游戏、给谁办 |
| 4 活动亮点 | 3 个核心亮点 |
| 5 后续计划 | 这场活动需要用 AI 产出哪些物料 |

**B. 宣讲海报（1 张）**：组数多、时间短时选用，信息浓缩同上。

**合格标准（初稿版）**

- [ ] 组名、成员、角色、游戏 IP、活动名称齐全
- [ ] 活动概念说清「办什么、给谁办」
- [ ] 第 5 页列出后续物料（可先列 3 项以上）
- [ ] 作品由工具生成，人工只做微调

### 6.3 收口（115-120'）

未达标的初稿，第 2 天开场 10 分钟补齐；不设课后作业。

## 八、整场讲师要点与常见坑

- 本场看「装好没有、能不能跑通一个任务」，不要求作品精致。
- 上手段一律按官网口径讲（四要素、四种上下文方式、结果区页签、任务状态），课后学员自己复看官网也能对上。
- 安装与登录最容易被个别学员拖住：讲师巡场 + 助教兜底，不因一人卡住全班。
- 三大组件演示只做 10 分钟，学员追问原理时统一回答「第 2 场开始拆」。
- 开场脉络段控制在 25 分钟内，讲成技术编年史会挤掉上手时间；三段例子不换题、不做竞品比较。
